# Complex scene diagnostic

`index.html?scenario=complex&backend=webgpu` and `backend=webgl-tsl` use exactly the same deterministic seed 712 layout, geometry, materials, animation clips, camera path and 1024px directional PCF shadows.

Assets are the real bundled Mapungubwe village, four crop mesh components, five Savanna vegetation types (authored LOD2), adobe walls, Kofi worker and buffalo skinned GLBs. There are 36 buildings, 432 crop components, 135 vegetation instances, 90 wall segments, 24 independently animated workers and 8 independently animated buffalo. Buildings, vegetation, crops and walls use shared instanced meshes; workers and animals retain actual skeletons and animation mixers. The nine 32m display chunks relocate one column every 1.5 camera-step seconds, exercising transform/frustum changes. This is preloaded render-only relocation, not asynchronous worker/IO streaming. CPU relocation events are exposed through metadata; no Wild Engine navigation or simulation is invoked.

This is a submission/skinning/material/shadow stress diagnostic, **not a migrated advanced campaign**. Common standard Node materials preserve the source textures, normals and mesh geometry but replace AfricanToon and all custom surface hooks. Ground is a neutral plane. There is no native shadow cache, game terrain/POM, water, VFX, campaign state, native LOD selector or actual streaming latency measurement. Accordingly, performance differences can support a backend diagnostic but cannot alone establish a full-game migration benefit or equivalent artistic output. Scenario B evaluates terrain and common shadow material behavior separately.

Memory: renderer object counts and JS heap are available from the harness. Neither is a measurement of actual GPU allocation. Dispose releases owned cloned geometry/Node materials, instanced buffers and skeleton bone textures, then the source Assets collection; shared source textures are owned once by Assets.

The worker source is the current runtime worker-actions.youngMale asset. Idle tool visibility uses the game's syncWorkerToolVisibility after sampling the clip, so hidden watering cans/crates/hoes are not submitted. Directional shadow render targets are explicitly disposed. The original smoke before this fix submitted unnecessary degenerate accessory geometry and must not be used as benchmark evidence.

Additional backend=legacy uses WebGLRenderer and MeshStandardMaterial with the identical assets, layout, animation, lighting and shadow settings. The other backends use MeshStandardNodeMaterial. This isolates the old renderer versus the common standard Node routes; it still does not reproduce AfricanToon. Standard BRDF intent is shared, but PCF shadow filtering implementations may differ. Image parity, particularly shadow edges, must be checked before attributing a timing difference to backend overhead. No legacy smoke or benchmark was run while the River export was active.
