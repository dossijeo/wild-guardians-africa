# Defensive-region navigation prototype (experimental, not integrated)

The saved Sabana day-12 state contains 266 living crops, 124 wall pieces, one intact gate, and one **ruined gate**. The physical perimeter is therefore open. The existing complete-component certificate rejected none of 1,924 crop-group checks, and 55,242 native `approachPath` calls produced 22 routes. Treating every crop as unreachable merely because it appears behind the drawn perimeter would be a false negative. The failure is primarily repeated bounded A* over a physically connected but awkwardly routed landscape, not proof of a sealed enclosure.

The QA-only scripts `tools/experiments/enclosure-access-prototype.mjs` and `benchmark-enclosure-access.mjs` build one shared exact-grid reachable field per origin/radius/geometry and retain native A* for possible destinations. AB/BA replays of the same 5-second Sabana tick kept the exact serialized state, but **eliminated no A* calls**: reference 16.57/16.65 s, candidate 18.63/18.72 s. The fields cost about 3.0 s to construct. On Gran Cañón day 7, the 1-second AB/BA replay also kept the state and the same 335 A* calls; reference 3.57/3.48 s, candidate 3.85/3.64 s. The existing relaxed reachability filter already excluded the disconnected points found by this stricter field.

`enclosure-route-tree-prototype.mjs` tested a shared route tree from an animal origin. On Sabana day 12 it reduced the tick to 5.39/5.32 s and the *observed calls to the wrapper* to 34, but the serialized state differed and successful target routes changed from 22 to 19. The tree can route through corridors outside the original bounded A* search and so changes target choices and movement; this is not a behavior-preserving optimization. Gran Cañón likewise produced a different state and increased wrapper calls from 335 to 847 despite a modest timing reduction. A negative-only variant preserved the Sabana state but was slower (23.77/24.00 s versus 16.16/16.99 s), with more wrapper calls. None of these candidates is enabled in `src/` or used by the campaign runner.

The results rule out simply layering a persistent flood field on the existing filters. A production enclosure index should first prove a physically closed component **for each animal radius**, then associate crops and attackable boundary segments with that component. The index must be invalidated only by changes to blocking geometry. An open gate or breach must keep the crop region connected and eligible for native movement; portal-based routing through such openings would be a separate, explicitly behavior-changing navigation proposal requiring attack, reservation, RNG and save/reload QA. The existing `closedRegions`, `searchedRegions`, `approachReachability` and 32-point checks should be consolidated only after a replacement demonstrates both fewer searches and no false negatives on the retained snapshots.

These prototypes intentionally do not implement long-lived region IDs, worker access routes, or incremental local updates: adding those before a successful connectivity filter would increase production complexity without a measured gain. The raw reports record per-run RSS deltas, but four sequential runs in one Node process share V8 allocations; they are insufficient to assert a reliable memory win. No claim is made about 14-, 30-, 60- or 100-night runtime on the prototype.

One exact simplification *was* retained in `src/simulation/raids.js`: group accessibility is evaluated once per crop component per animal target selection, instead of once per crop. The Sabana profile went from 1,924 to 119 group checks (about 292 ms to 8 ms); it left all 55,242 `approachPath` calls untouched. The 5-second AB/BA tick had identical serialized states and times of 16.25/16.91 s before versus 16.61/16.98 s after, so there is no demonstrated end-to-end speedup in this checkpoint. The Gran Cañón 1-second replay also had identical states (4.08/3.52 versus 3.57/3.29 s). This is code simplification, not the requested structural runtime breakthrough.

The separate mixed-barrier bot pilot on seed 123 ended in a native defeat after night 22; the earlier reference defeated at night 24. Recognition of walls joined to solid obstacles has not been shown to improve survival, and these two campaigns do not isolate attack variation from bot decisions. No 60- or 100-night run was launched on the rejected navigation prototypes.
