# Defensive-region navigation prototype (experimental, not integrated)

The saved Sabana day-12 state contains 266 living crops, 124 wall pieces, one intact gate and **26 ruined wall modules** grouped into ten possible breaches, including one ruined gate. The ruined gate's centre is traversable at radii 0.4 and 0.7 but blocked at 1.1 and 1.5; other parts of its eight-module breach are passable even at radius 1.1. A two-module breach elsewhere is passable at 1.1 and 1.55. The existing complete-component certificate rejected none of 1,924 crop-group checks, and 55,242 native `approachPath` calls produced 22 routes. A radius-specific connectivity proof is needed before ruling out crops behind this perimeter. See `day12-breach-portal-probe.json`.

The QA-only scripts `tools/experiments/enclosure-access-prototype.mjs` and `benchmark-enclosure-access.mjs` build one shared exact-grid reachable field per origin/radius/geometry and retain native A* for possible destinations. AB/BA replays of the same 5-second Sabana tick kept the exact serialized state, but **eliminated no A* calls**: reference 16.57/16.65 s, candidate 18.63/18.72 s. The fields cost about 3.0 s to construct. On Gran Cañón day 7, the 1-second AB/BA replay also kept the state and the same 335 A* calls; reference 3.57/3.48 s, candidate 3.85/3.64 s. The existing relaxed reachability filter already excluded the disconnected points found by this stricter field.

`enclosure-route-tree-prototype.mjs` tested a shared route tree from an animal origin. A fresh AB/BA replay on Sabana day 12 measured 15.61/16.35 s native versus 5.35/5.21 s with the tree; native animal searches fell from 55,257 to 26. The resulting states differ, but the two candidate runs match each other exactly. At the **same 34 path requests** in a paired audit, the tree found eight native-collision-valid routes absent from bounded A*, lost none of the native routes, and returned no invalid segments. The total successful target routes change from 22 to 19 because these new routes alter subsequent target choices, not because three identical requests failed. Gran Cañón day 7 measured 3.38/3.30 s native versus 3.17/3.14 s with the tree; its native searches rose from 340 to 769 and wrapper calls from 335 to 847. Both candidate runs also matched each other there. A negative-only variant preserved the Sabana state but was slower (23.77/24.00 s versus 16.16/16.99 s). The tree therefore merits continued work, especially on Canyon fallback/search amplification, before production promotion. See `day12-route-tree-abba-property.json`, `day12-route-tree-paired-audit.json`, `canyon-day7-route-tree-abba-property.json` and `canyon-day7-route-tree-paired-audit.json`.

The results rule out simply layering a persistent flood field on the existing filters. A production enclosure index should classify physically passable breaches **for each animal radius**, then associate crops and attackable boundary segments with regions. The QA-only `breach-portal-prototype.mjs` groups consecutive ruined wall modules and assigns species width classes once per navigation topology version; it verifies possible crossings with native collisions at build time. Straight verified openings become reusable graph edges. Corners, natural obstacles and unverified openings remain unknown rather than becoming false negatives. The day-12 table took about 103 ms to build; subsequent access is a lookup. The current route tree does not yet consume this portal table. The existing `closedRegions`, `searchedRegions`, `approachReachability` and 32-point checks should be consolidated only after a replacement demonstrates a meaningful gain without physical errors.

These prototypes do not yet implement long-lived region IDs, worker access routes, or local incremental updates. The raw reports record per-run RSS deltas, but four sequential runs in one Node process share V8 allocations; they are insufficient to assert a reliable memory win. No claim is made about 14-, 30-, 60- or 100-night runtime on the prototype.

One exact simplification *was* retained in `src/simulation/raids.js`: group accessibility is evaluated once per crop component per animal target selection, instead of once per crop. The Sabana profile went from 1,924 to 119 group checks (about 292 ms to 8 ms); it left all 55,242 `approachPath` calls untouched. The 5-second AB/BA tick had identical serialized states and times of 16.25/16.91 s before versus 16.61/16.98 s after, so there is no demonstrated end-to-end speedup in this checkpoint. The Gran Cañón 1-second replay also had identical states (4.08/3.52 versus 3.57/3.29 s). This is code simplification, not the requested structural runtime breakthrough.

The separate mixed-barrier bot pilot on seed 123 ended in a native defeat after night 22; the earlier reference defeated at night 24. Recognition of walls joined to solid obstacles has not been shown to improve survival, and these two campaigns do not isolate attack variation from bot decisions. No 60- or 100-night run has yet been launched with the route tree.

Raw reports: `day12-enclosure-access-prototype-abba.json`, `day12-enclosure-negative-prototype-abba.json`, `day12-enclosure-route-tree-prototype-abba.json`, `canyon-day7-enclosure-access-prototype-abba.json`, `canyon-day7-enclosure-route-tree-prototype-abba.json`. All times are wall-clock on this host, not player-visible frame times.

## OpenRA architectural reference

OpenRA's [`IPathFinder` contract](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Mods.Common/TraitsInterfaces.cs) and [`PathFinder` implementation](https://github.com/OpenRA/OpenRA/blob/bleed/OpenRA.Mods.Common/Traits/World/PathFinder.cs) distinguish a cheap *might exist* check from a path search. Its conservative blocker check may return false positives, but a negative answer guarantees no path. This is the appropriate contract for a Wild Guardians region index: uncertain edges and fractional connectors return “possibly connected” and use native navigation. OpenRA also provides multi-target and predicate searches, but warns that they can be slower than a single known destination and that reversing a search can change semantics when one endpoint is inaccessible. Those operations should be reserved for finding an enclosure entry or an attackable barrier once, not invoked for every crop. These are design principles only; no OpenRA code is copied.

For the next candidate, the smallest useful interface is `regionFor(point, animalRadius, geometryVersion)` and `mightConnect(regionA, regionB)`, plus a finite list of *native-collision-verified* barrier contact points and breach portals. Crop group IDs can remain separate from region IDs so replanting does not rebuild geometry. A portal is species-specific: the same visual gap may be passable to one animal and blocked to another. A closed fixture should reject per-crop searches; destroying a wall must invalidate that proof. Promotion requires physical route checks, deterministic same-version repeats, save/reload QA and a measurable runtime gain. Exact agreement with old routes or serialized state is not required.

The additional native `closed-walls` fixture probe demonstrates that the existing relaxed reachability filter already handles this closed case: with 100 connected crops and 12 animals it issued **zero crop A*** calls and 12 successful wall-approach calls. Destroying two adjacent wall pieces reopened the enclosure; all 12 animals then obtained crop approaches in 12 calls. The group-certificate counter itself did not reject either case, but the existing prefilter and native collision checks selected the correct target class. See `enclosure-closure-baseline.json`. The day-12 checkpoint has several physically passable breaches; its bottleneck is repeated bounded searches to individual points, which the shared tree largely avoids. The next task is to handle portal connectivity and fallback amplification without making routing inaccurate.

## Discrete-grid reduced prototype

`logical-animal-grid-prototype.mjs` supplies 16×16 logical chunks per animal radius. The route tree now consults the grid for integer-node walkability and edges; native geometry fills each cell/edge once per topology version. Fractional actor and target connectors, plus physical movement, retain native collision checks. The first eager-chunk implementation calculated 73,728 cells and 422,312 edges for the Sabana 5-second replay and took 22.15/22.16 s—worse than the 15.68/16.03 s baseline. It is retained as negative evidence in `day12-grid-tree-abba-property.json`. The lazy-chunk implementation calculated 49,593 cells and 56,678 edges and took 5.22/5.21 s versus 15.89/15.89 s baseline; both candidate runs were deterministic (`day12-grid-tree-lazy-abba-property.json`). A paired audit found eight valid routes absent from bounded A*, no lost native routes at the same sampled requests and no invalid segments (`day12-grid-tree-paired-audit.json`).

The Gran Cañón day-7 1-second replay took 3.22/3.09 s versus 3.44/3.27 s native, but invoked more native searches (769 versus 340) and more total approach queries (847 versus 335). That is a weak/unstable gain, not evidence of a general Canyon win (`canyon-day7-grid-tree-abba-property.json`). The paired audit did not find an invalid route, but instrumentation of native navigation can itself change cache state and query order; do not treat its total call count as an independent benchmark. `tests/enclosure-route-prototype.test.js` covers no walls, closed walls, a physical breach, portal-table invalidation, corners left unknown and deterministic save/reload on a short native fixture. The table is **not yet consumed by the route planner**; it currently proves that species-specific breach lookup can be constructed once per topology epoch and identifies graph edges for later integration. No long-campaign improvement or memory reduction is yet claimed.

## Destination and shared-component experiments, 13 October 2026

The 14-day Sabana cashflow controls expose why a five-second checkpoint is insufficient. The original per-origin grid tree cost 184.8 seconds of accumulated `Game.tick`, versus 115.1 seconds with native navigation. The adaptive version, switching only after 5,000 failed native searches in a topology epoch, cost 107.6 seconds but still used 38,758 native trials and built 12 independent trees. These are different game trajectories, so the totals measure practical campaign cost rather than an exact same-state speed ratio. The diagnostic outputs are retained in `pilot-good-sabana-123-14-{grid-tree,native,adaptive-grid-tree}-cashflow*`.

Three QA-only alternatives were tested and retained as negative evidence. The per-group closed-region classifier rejected only 12 of 119 group checks in the Sabana five-second tick, leaving 55,195 native searches and taking 16.86/16.64 seconds versus 15.71/16.66 baseline. A reverse field seeded separately for each crop group built 111 fields and took 19.63/20.40 seconds. A global reverse field built four fields and reused them 13 times, but its four fields all touched their finite bounds; 9 of 15 misses therefore could not safely reject a path. It still left 55,272 native searches and took 18.06/19.28 seconds. On Canyon it found no shared crop route, left 340 native searches and cost 3.77 seconds. These trials show that merely sharing a goal field does not solve target selection when its finite search cannot certify disconnection. See `day12-shared-region-abba.json`, `day12-shared-goals-abba.json`, `day12-global-goals-abba.json`, and the diagnostic JSON files.

The exact shared-connectivity prototype builds one animal-grid component per radius and reuses it across actors. In Sabana it built four components, reused them 240 times and skipped 18 crop groups, but still allowed 49,851 native searches and took 20.79 seconds. In Canyon, combining this index with the route tree reduced wrapper approach calls from 847 to 2, but 34,460 endpoint checks made the tick slower (4.47 seconds). A tree-derived endpoint prefilter likewise reduced Canyon calls to 98 but increased the tick to 3.76 seconds. Both remain diagnostic prototypes, not the recommended mode.

The **shared incremental tree** reuses a route field across animal starts whenever the new actor has a physically valid connector into it. When separate seed roots meet only through the original fractional actor position, the route explicitly traverses that point. Reverse-leg edges are checked in the travel direction; native `smoothPath` reduces long shared-tree detours. Unlike the old full build, its frontier persists and expands only until a requested destination or new actor connector is reached. The topology-versioned breach table now contributes native-verified species-specific portal edges to the discrete route graph. On the Sabana day-12 five-second checkpoint, the last portal-enabled candidate built **4 trees**, reused them **11** times, expanded **21,031** nodes, evaluated **24,455** cells and **23,541** grid edges, and traversed a breach portal twice. The candidate took **3.58 seconds** versus **15.91/16.35 seconds** in the frozen native AB/BA reference. A paired same-request audit found 8 candidate-only physically valid routes, 11 routes found by both, 15 found by neither, zero native-only routes and zero invalid candidate segments. The matched AB/BA run before the portal addition took 3.60/3.49 seconds with identical candidate hashes; the portal addition has so far had one candidate replay and a physical paired audit, not a fresh AB/BA.

On Canyon day 7, the shared tree built one field and reused it for 81 origin queries. It reduced native A* from 340 to 5 and showed **zero prototype fallbacks**. Wrapper approach calls grew from 335 to 847 because target choices changed and repeatedly queried service points that the shared field rejected cheaply. The AB/BA wall time was 3.00/2.97 seconds versus 3.40/3.31 seconds native. The 764 previously reported fallbacks belong to the earlier per-origin prototype and are not present in the shared-tree mode. The paired audit found no invalid route and no native-only same-request route. The Canyon improvement remains small because target enumeration and other tick work dominate; the endpoint prefilters tested so far cost more than they save.

The new mode remains **QA-only** (`--navigation-mode shared-incremental`). A first launch with a dirty tracked tree was correctly refused by the evidence harness and recorded as `incomplete-harness-error`, not a game defeat. The subsequent frozen 14-day result follows below; no 30-, 60- or 100-night result exists for this mode. Although the portal table is now used, the field still spans the crop/structure bounds of a raid and does not yet provide stable named regions, worker access reuse, or a complete region/portal/target/local-route production architecture. Promote nothing to `main` until the campaign and wider physical/persistence tests support it.

The frozen 14-day Sabana cashflow pilot at `e805b18b` completed all 14 nights. It **did not sustain** the checkpoint speedup: `Game.tick` accumulated 182.5 seconds versus 115.1 seconds for the native control, although it improved on the earlier always-on grid tree's 184.8 seconds. It built 88 fields (versus 236 earlier), reused them 128,587 times and spent 48.0 seconds on field construction. The remaining cost includes 149,035 rejected approach endpoints, showing that repeatedly enumerating individual crop samples is still the dominant architectural problem. The game trajectory differs (day-14 money 849 versus 629; maximum living crops 270 versus 277), so the timing comparison is practical campaign cost, not same-state equivalence. See `pilot-good-sabana-123-14-shared-incremental-v2` and the matched controls.

A QA-only batch-target hook then tried to consume one completed shared tree to select a crop from whole prioritized groups. Its first complete-field attempt returned no improvement on Sabana because all 16 invocations fell back before the field became complete. Warming one candidate point made Sabana's five-second tick 3.36 seconds and reduced wrapper route calls from 34 to 22, but Canyon scanned 34,176 individual service points and regressed to 4.11 seconds versus 3.00/2.97 seconds for the unbatched shared tree. This **does not satisfy** the goal of eliminating 32 samples per crop; it is retained as negative diagnostic code only. See `day12-shared-batched-diagnostic.json` and `canyon-shared-batched-diagnostic.json`.

A further QA mode, `adaptive-shared-incremental`, combines the proven shared incremental tree with the earlier 5,000-failed-native-query activation threshold. On the frozen Sabana five-second state it took 5.46 seconds, built four shared trees and avoided the rest of the 55,242 native route attempts after activation. It is a pragmatic candidate for reducing *campaign* overhead, not the final region-first architecture. A frozen 14-day pilot must establish whether it actually helps; do not extrapolate from this checkpoint. None of these navigation modes changes production game rules, and no 30/60/100-night campaign is claimed.

The adaptive shared 14-night pilot subsequently completed with 121.5 seconds accumulated `Game.tick`, compared with 115.1 seconds for the matched native cashflow control and 107.6 seconds for the older adaptive grid-tree. It made 52,877 native trials before five activations. It is therefore not a sustained speed win.

## Region-first crop selector, 13 October 2026

The experimental `region-goals-tree` mode passes prioritized crop groups to a shared selector. For each animal radius and topology version, it builds a logical-grid connected component, derives crop interaction points from nearby reachable cells instead of enumerating a 32-angle ring, and uses the existing shared incremental route tree for the chosen local connector. Physically occupied points and shields retain the native eligibility checks. A group proven disconnected is remembered for other animals in the same component. This is QA-only; the fallback remains available for uncertain connectivity.

In the frozen Sabana day-12 five-second AB/BA replay, the first full-component version took 5.20/5.50 seconds versus 16.38/17.23 seconds native. It made 22 approach queries, 43 native path searches, generated 237 service points and built four route trees. The exact target route choices changed, which is allowed if the physical paths remain valid. On Canyon day 7 it took 0.49/0.41 seconds versus 3.69/3.45 seconds native, with five native searches and no crop service point generated because the crops were outside the animal component. Both candidate pairs were deterministic. See `day12-region-cell-goals-abba.json` and `canyon-region-cell-goals-abba.json`.

That checkpoint gain **did not survive the first campaign**. The ten completed days accumulated 74.4 seconds of `Game.tick` versus 38.0 seconds over the same days in the matched native control. On night 11 a hyena remained walking against an invalidated first route leg and the harness correctly stopped with `incomplete-harness-error`, not a game defeat. The saved partial state and negative timings remain under `pilot-good-sabana-123-14-region-cell-goals-v1`. A zero-progress animal with a statically blocked first leg now discards the route and retries through normal targeting; the recorded state reproduces the recovery and `tests/actor-motion.test.js` covers it.

The follow-up component index expands only until a candidate group's service cell is reached, retaining its frontier for later queries. On Sabana's frozen checkpoint it visited 24,855 cells rather than 52,565 and reduced candidate time to 3.71 seconds in a single diagnostic run; on Canyon it still had to exhaust the inaccessible component, took 0.57 seconds, and reused the group-disconnection decision for the remaining animals (178 crop targets examined in total instead of 1,068). These are single candidate runs, **not AB/BA or sustained campaign evidence**. The revised 14-night pilot is running separately. No 30-, 60- or 100-night campaign should be inferred from these checkpoint results.

That revised 14-night pilot completed without the animal-route stall, but remained too slow: **173.1 seconds** accumulated `Game.tick` versus **115.1 seconds** native, with 125 components, 952,998 visited region cells and **62.5 seconds** spent constructing/expanding components. It selected 303 crop routes after 13,004 crop candidates, versus the former 32-per-crop ring. Its final money (927) and maximum living crops (261) differ from the native trajectory (629 and 277), so these are practical performance comparisons and must not be read as equivalent-state speedups. See `pilot-good-sabana-123-14-region-incremental-v2`.

The next candidate probes at most two nearby members of the highest-priority crop group through the existing shared tree before paying for a full region query. It still uses the regional index to resolve failed group access and barriers; it never reintroduces the 32-angle normal path. In fresh AB/BA checkpoint runs, Sabana took 3.46/3.41 seconds versus 16.84/16.70 seconds native, found six of sixteen targets via the cheap group probe, and built three regions rather than four. Canyon took 0.55/0.52 seconds versus 3.80/3.44 seconds native; the component was built to reject inaccessible crops, while 15 later group checks reused that decision. Both candidate pairs were deterministic. See `day12-region-probe-abba.json` and `canyon-region-probe-abba.json`. A new 14-night pilot is required before extending to 30 nights.

That third 14-night pilot has now completed: **167.2 seconds** accumulated `Game.tick`, including **24.6 seconds** of component traversal, against the same **115.1-second** native control. It remains a sustained regression despite reducing the full-component prototype's 62.5-second traversal. The retained report is `pilot-good-sabana-123-14-region-probe-v3/report.json`. The duplicated work is now clear: the route tree and the component index both explore the same walkable grid. Continuing to tune probe thresholds would preserve that architectural duplication.

The fourth QA-only candidate, `tree-group-selector`, removes the second component traversal entirely. It selects crop service points from nearby cells and consults the shared route tree's visited cells. This is deliberately a single navigation exploration rather than another region filter. The Sabana day-12 AB/BA checkpoint measured **3.44/3.28 seconds** against **15.87 seconds** for the first native run; it built four trees, reused eleven, and made 22 approach queries. The selector performed 16 group queries and examined 43 targets; no component traversal occurred. The candidate pair was deterministic. The Canyon checkpoint exposed a correctness boundary: the actor's tree reached its finite search boundary, so a crop outside its visited cells cannot safely be declared unreachable. The conservative fallback produced **3.21/3.21 seconds** versus **3.61/3.34 seconds** native in the first AB/BA run, but returned to 848 approach queries. It is an uncertain-access case, not evidence of a closed enclosure. The follow-up run with a corrected local connector check remained about **3.03/3.00 seconds** versus **3.31 seconds** native. Reports: `day12-tree-group-selector-abba.json`, `canyon-tree-group-selector-abba.json`, `canyon-tree-group-selector-abba-v2.json`. These are checkpoint measurements; sustained campaign evidence is still required. The selector is a QA mode only and is not enabled in production.
