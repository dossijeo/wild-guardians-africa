# Native crop intent after a confirmed breach

The focused `a confirmed enclosure breach reconsiders other wall attackers at an event boundary` fixture in `tests/spatial-native-raid.test.js` exposes an unresolved migration gap. With the current bundled WASM, both wall attackers are woken by the confirmed `StructureRuined` event, but their first `nav_intent_plan_attack_crop` calls return `unknown`. The first call performs two region queries and nine native route queries; the second performs one region query and no route query.

At the same event boundary, the established selector finds a physically valid crop approach for animal 19. A direct call to Wild Engine's `spatial_world_route_cached` from that animal's current coordinates to the selected approach returns a two-point route. Thus the `unknown` result is not proof of an inaccessible crop or missing route. The transitional event-only fallback in `raids.js` preserves immediate tactical reconsideration; normal unresolved selections remain in the bounded waiting state.

I tested a C++ prototype that enumerated the four floor/ceil connectors of each fractional attack point instead of only its rounded cell, and then allowed a continuous direct segment to bypass a negative weak-region approximation after the crop group had been classified as accessible. The rebuilt WASM still returned `unknown` with the same two/nine and one/zero query counts in this fixture. The source prototype and its deliberately failing assertion were reverted. No unverified native fix is included in the PR.

The next investigation should instrument which crop and interaction point each of the nine route queries uses, and compare those exact points with the valid approach. It should then correct candidate generation or ordering inside `nav_intent_plan_attack_crop`, not add ordinary per-tick JS searches. Preserve the physical route validator and the distinction between `unknown` and `blocked`.

The local host reached zero free bytes while the isolated Emscripten image was being used. The automatic review rejected recursive removal of the generated `dist` directory. Only three explicitly named, regenerable files from this worktree's `dist` output and the generated candidate WASM were removed; no Docker volume or unrelated image was pruned. The worktree was restored to the passing branch state after the prototype. Further WASM builds need sufficient free disk space before beginning.
