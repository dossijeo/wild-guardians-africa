# Native crop intent after a confirmed breach

The focused `a confirmed enclosure breach reconsiders other wall attackers at an event boundary` fixture in `tests/spatial-native-raid.test.js` exposes an unresolved migration gap. With the current bundled WASM, both wall attackers are woken by the confirmed `StructureRuined` event, but their first `nav_intent_plan_attack_crop` calls return `unknown`. The first call performs two region queries and nine native route queries; the second performs one region query and no route query.

At the same event boundary, the established selector finds a physically valid crop approach for animal 19. A direct call to Wild Engine's `spatial_world_route_cached` from that animal's current coordinates to the selected approach returns a two-point route. Thus the `unknown` result is not proof of an inaccessible crop or missing route. The transitional event-only fallback in `raids.js` preserves immediate tactical reconsideration; normal unresolved selections remain in the bounded waiting state.

An initial C++ prototype enumerated floor/ceil connectors and considered a direct continuous segment. The first local comparison appeared unchanged, but the raid test was hardcoded to load the bundled WASM and ignored `WILD_ENGINE_NATIVE_ROUTE_WASM`. That comparison therefore **did not execute the candidate binary** and cannot establish that the prototype failed. Its source edits were reverted. The test now accepts the explicit candidate path, and a separate PR job builds and exercises the native candidate before it can replace the bundled binary.

The first correctly exercised remote candidate still returned `unknown`. Native diagnostics then identified the failure stage: crop 2 was selected, its preferred physical route contained two points, and `nav_intent_register_attack` returned `-5`. That function was passing every full route segment to `spatial_local_clear`, which deliberately rejects any segment longer than 1.5 m because it is only a short connector predicate. The route planner can legitimately produce a longer shortcut after checking it in subsegments with `clearWorld`. The next candidate reuses that same physical sweep when registering an attack intention. The focused test requires a `found` native result at the breach boundary. This fixes an internal route-validation mismatch; it does not relax wall, terrain or water collision rules.

The local host reached zero free bytes while the isolated Emscripten image was being used. The automatic review rejected recursive removal of the generated `dist` directory. Only three explicitly named, regenerable files from this worktree's `dist` output and the generated candidate WASM were removed; no Docker volume or unrelated image was pruned. The Emscripten image downloaded for this probe was removed. Native candidate builds now run on the PR runner until local disk space is available.
