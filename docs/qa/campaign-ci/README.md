# Manual intensive campaign CI

`Intensive campaign QA` runs the existing responsible strategy for100nights
in one selected native biome/culture. Manual dispatch only: no publishing,
no gameplay changes, no asset promotion and no job per ordinary commit.
Each checkout is frozen to its triggering SHA; the existing runner records
source hashes, paid commands, physical crop/crate deliveries, daily worker
contracts, actual damage, economic audit and the separate activity gate
(strictly below25%). Seed712 and the existing mixed reinvestment policy are
unchanged. Completing one case cannot approve the30-combination matrix.

Optional poor management runs the existing six-biome10-night diagnostic:
no expanding labour/repair reserves, ordinary near-camera raids and burst
planting. Defeats and survivals are retained without forcing a loss.

The campaign step has330minutes, leaving30minutes in the job for uploads.
Success, failure and partial state/status/checkpoints/process output are
uploaded with `always()`, retained30days. A timeout leaves incomplete evidence;
`running` in a retained status file does not imply a live process after the
job is terminal. Read the actual GitHub job outcome before classifying a run.
No simulated rendering, physical mobile, perceptual audio or whole release
acceptance is claimed by this domain-only job.

Workflow syntax/expressions validated with official actionlint1.7.12;
Windows release ZIP matched its official SHA-256 checksum. No new project
dependency. Campaign execution results are separate evidence and must be
inspected after the dispatched process completes.
