# Crop route epoch experiment — QA only

Production already preserves static navigation caches when a paid planting removes no props. It still increments the route epoch, causing workers to replan. This candidate removes only that increment for the identical state and an empty removed-props list. Real prop removal and state replacement retain full rebuilds. No production code or assets are changed.

Native historical Sabana/Musgum dense farm, ordinary postgame continuation and paid hiring of 112 older women. Ten separated dead-crop positions are checked against current native placement, live crop spacing, zero suppressed props and outbound/inbound routes. Ten normal millet purchases occur one per simulated second. No terrain, speed, money, task or growth overrides. The input snapshot remains in the linked historical QA directory; receipt binds its compressed SHA-256.

AB/BA: four arms of 100 ticks at 0.1 simulated seconds, 25 warm and 75 measured. Plant command time is recorded separately; state serialization and validity probes are outside tick timing. Reference medians: 4.7174/4.6663 ms; candidate: 4.0917/3.8932 ms. Combined median: **4.7174 → 4.0576 ms (−13.99%)**. Path calls: **1,539 → 299 per arm (−80.57%)**. This is one CPU experiment with background campaigns, not total frametime, GPU or mobile evidence. Reference/candidate trajectories differ, so timings are not equal-work proof of a transparent optimization.

Each repeated arm has identical hashes within its implementation. Full-state reference/candidate hashes differ immediately because of epoch metadata. Excluding only state navigationVersion and worker/animal pathVersion, the first difference is tick 10, immediately after the second planting. Two valid-before active workers become invalid in each arm; the candidate does not fix those existing incidences.

An untimed paired diagnosis confirms real differences rather than metadata alone. At tick 10, 25 workers differ, maximum separation 0.0829 m; at tick 20, 57 differ, maximum 0.9741 m; at tick 50, 101 differ, maximum 0.7908 m; at tick 99, 118 differ, maximum 1.6415 m. The retained path and its newly replanned counterpart have different waypoints. By tick 99 a plant also has different growth and checkpoint water state: reference manual with zero wait, candidate due with 23.75 wait. Task completion timing therefore changes. State-difference listings are capped at 80 entries per checkpoint; both complete terminal projections are archived.

**Not approved for production.** The saving is worth investigating, but route retention needs full-workday/restore/attack/native-terrain validation, including failures and dynamic obstacles. Different trajectories are not automatically a bug, nor evidence of safety. Existing route-epoch tests deliberately require the established behavior; they were not weakened to admit the experiment. Reusing static caches remains the production behavior.

Four background campaigns (35912/49032/41320/41304) were confirmed live. Loading agent deferred native QA until benchmark completion. Repair agent reports its last Blender finished 3.24 seconds before receiving the reservation, which was sent after dispatch; pre-reservation overlap cannot be excluded. No root GPU activity. The later untimed diagnosis overlapped loading visual QA and is explicitly not performance evidence.
