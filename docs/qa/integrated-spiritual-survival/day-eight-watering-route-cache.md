# Day-eight native worker-route cost

The cooperatively stopped v116 state at day eight, time 276 s, was replayed locally without changing the save. It has 190 living crops, 175 queued tasks, 15 workers and 82 paid wall pieces; no raid is active. The failed rectangular contour alternatives are not the dominant cost: the nine direct quotes, proofs and bounded routing attempts reconstructed from the exact day-seven terminal state took about 6.3 s together. A single native `Game.tick(state, 1, nav)` on the stopped day-eight state took 1.9–2.4 s without instrumentation, across five ticks.

The CPU profile of five such ticks concentrates in navigation's swept segment checks, `wateringRoute`, the building-corner shortcut and fractional walkability. A diagnostic wrapper counted 49,030 `nav.path` calls (46,580 watering destinations) and 469,943 `segmentClear` calls in one simulated second. The engine divides that second into ten 0.1 s steps; idle workers repeatedly probe the same blocked watering targets from exactly unchanged coordinates. This is a real simulation cost, independent of the QA defense search.

The candidate caches only **negative** `wateringRoute` results for an exact worker position/radius, plant identity/position/species and live navigation epoch. The cache is scoped to one navigator and bounded to 8,192 entries. Moving the worker, changing the navigation version, field or obstacle array triggers a full retry. Successful routes are never cached or shared. On the same stopped state, the first candidate tick took 0.84 s with diagnostic wrappers, with 7,108 path calls and 78,785 segment checks. The old instrumented tick took 2.60 s; this is a local CPU comparison, not yet a full-campaign ratio. The relevant watering, canyon, detour, diagnostic and route-clearance tests pass 30/30. A native campaign replay is required to verify identical task completion and economic rows before this candidate can be accepted.

The native replay `pilot-v117-water-route-good-sabana-123-eight/` completed eight nights without defeat. It ran from 17:59:42 to 18:02:54 UTC, about 3 min 12 s. All first seven daily JSON rows match the v115 baseline byte-for-byte. At day eight it finished with 602 coins, 184 live crops, 62 delivered crates and 40 coins of actual wall purchases. The previous v116 run stopped at day-eight time 276 s, so it has no completed eighth row to compare. However all 1,260 ledger entries present in that stopped state appear with identical exact values in the v117 terminal ledger. The candidate retains the prefix of real purchases, wages, repairs and deliveries through that point. This does not alone prove every worker pose or task at time 276 was identical; a full same-horizon baseline or more detailed checkpoint comparison is still needed before promoting the cache as semantically neutral. The web production build succeeds. This experimental balance branch predates the `test:playable` package script on current `main`, so its absence is not reported as a passed check.
