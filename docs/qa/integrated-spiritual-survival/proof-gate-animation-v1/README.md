# Gate animation invariant: isolated QA candidate

The live campaign CPU profile identified repeated native perimeter certification as the dominant virtual-policy cost. Changing gateOpen invalidated full JSON keys even though hostile static navigation treats the full gate footprint as an obstacle. The opt-in candidate removes only gateOpen from objects explicitly identified as wall gates. All other fields, topology versions, terrain, methods, proposed geometry and target tuples still participate in existing invalidation. Defaults remain off. No production navigation, policies, prices, damage or live campaign sources were changed.

Worker access is recomputed on every call using the native V2/V3 worker proof; animated gate access is never certified by the cached animal proof. The opt-in wrapper rejects custom worker proof adapters and overridden physical navigation methods. Damage, material, position, gate identity and navigation version changes still invalidate coverage.

## AB/BA native diagnostic

Retained snapshot: 233 living crops, one existing native gate, one proposed wall. Four fresh state/navigation arms, baseline/candidate/candidate/baseline, each queried at controlled gate phases 0 then 1. This is a static certification diagnostic, not simulated physical gate motion or a campaign. All eight normalized physical certificates were identical, quotes unchanged, state unchanged by certification, absent workers rejected, and the subsequent real paid native wall purchase produced byte-identical serialized states across arms.

Mean cold baseline 33.688 s; cold candidate 33.160 s. Mean after gate-phase change: baseline 33.134 s; candidate 0.231 s, 99.30% observed reduction in that particular repeated query. Concurrent campaign/test CPU makes these non-isolated timings; this does not establish GPU improvement, overall campaign speed, or final balance acceptance. Cold work is not faster.

The first comparison stopped because reusedComponents differed by one. That field only counts warm component reuse in native-reused-service-component-proof-v2; the negative output is retained losslessly. The revised comparator excludes only that field under its exact native service-proof reason, plus terrain execution diagnostics. Validity, blocked/certified poses, connector checks, region counts, target coordinates and worker results remain compared. Complete unnormalized proofs are retained in benchmark-full.json.gz, so excluded counters remain inspectable.
