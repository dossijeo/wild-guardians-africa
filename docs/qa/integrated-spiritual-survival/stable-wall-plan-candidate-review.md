# Stable prospective wall metadata: isolated QA candidate

The active v116 100-night campaign is unchanged. This experiment does not alter
production, the campaign runner, native purchase IDs, gate selection, damage,
prices, RNG or the player strategy. It is not a campaign result.

## Diagnosed cause and candidate

The retained v115 proposed final wall piece keeps exactly the same geometry,
material, gate state and all other physical properties after five native seconds.
Crate deliveries nevertheless advance global entity/event counters, changing its
prospective `id` and `created`. The existing proof treats this as a new layout,
discarding the expensive positive animal certificate.

`stable-prospective-wall-plan-candidate.mjs` retains the first native quote's
virtual metadata within one record per navigator. It runs only after native gate
selection. It aliases new/unbuilt pieces and their preview/update references;
actual structure updates keep their real IDs. Every other plan field, native
navigation epoch, obstacle, structure, village, suppression and culture must
remain identical. State identity must match. Real entities claiming a retained
alias invalidate it; duplicate or unsupported proposals are not transformed.
Inputs are never mutated. Workers still receive fresh native checks on every call.

The comparator injects this helper into copied proof modules via in-memory module
URLs. No existing runtime file is edited or enabled by the experiment.

The first cold certificate still costs about 22 seconds. The reduction applies
to unchanged-layout repeated checks, not all perimeter searches or initial load.
Times are sequential CPU diagnostics with the live campaign also running;
they are not isolated performance acceptance, GPU measurements or gameplay FPS.

All 21 serialized native states match exactly across the two copies, including
physical worker deliveries and the ledger. All three fresh worker proofs match.
The initial complete physical certificate matches. The later candidate explicitly
retains a positive superset certificate after six crops are harvested; its counts
describe original coverage, not freshly visited targets. A separate native view
re-certifies every surviving crop and operational center, from each of the five
retained exterior origins and using all 32 attack poses. All pass. Proposed plans
and copied states remain unchanged by proofs.

The exact JSON records source/snapshot hashes, every checkpoint, terrain counters,
retained coverage and independent final checks. It remains `promoted: false`.

## Tests and remaining scope

74 focused tests pass, including 15 new metadata invalidation/ownership tests,
the existing positive-certificate cache tests, incremental native target coverage,
worker access and exact terrain/fluids checks. Evidence:
`stable-wall-plan-candidate-tests.txt`.

This warrants further native candidate validation for actual purchases, edited
perimeters and mixed materials before enabling it in a future campaign protocol.
It does not justify changing the live v116 protocol or asserting 100-night
survival, economic acceptance, broader biome acceptance or player inactivity.
