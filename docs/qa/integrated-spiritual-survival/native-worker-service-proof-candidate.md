# Native worker service proof candidate

`tools/native-worker-service-proof.mjs` is an experimental standalone QA helper. It is deliberately not imported by `native-perimeter-proof.mjs`, the defense policy or any live campaign. The active v105 campaign retains its frozen sources.

The candidate replaces the inappropriate crop-pivot worker destination with the existing native watering-service geometry. It checks every non-incapacitated, non-home worker against a body-valid living crop, without skipping an inconvenient actor. It then checks every living crop from its own operational centre, validating the watering pose's height/reach and requiring a native return route to that centre's nearest authored delivery edge. Failed searches reject the candidate as unproven; they are never accepted as enclosure evidence.

It does not alter the independent animal-service enclosure checks, gate construction, economic charges, wall quoting or production navigation. No contour becomes paid or approved simply because this helper returns valid. The saved state is unchanged in the native positive regression.

The native retained Canyon case checks ten workers and 123 living crops successfully. Negative regressions reject absent workers, orphan crops, a solid footprint covering the service area, and a failed return route despite successful watering. Together with the positive/native-boundary enclosure regressions, 11 tests pass. The synthetic failed-return query is a focused guard test; it is not reported as a native campaign failure.

This adds one linear crop-service sweep plus worker checks per prospective proof. Concurrent local test durations are not controlled performance measurements. Before integration, inspect its cost on dense farms and ensure repeated defense planning uses the existing geometry epochs without stale worker/crop decisions. After v105 is terminal, integrate into a fresh frozen candidate, preserve historical results and revalidate Canyon closure, physical gates, worker motion, paid repair and animal interception. Do not attribute an economic improvement to this unintegrated helper.
