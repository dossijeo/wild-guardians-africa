# Q15 actual-cash renewal candidate

v99 Q14's native economic defeat exposes a daily hiring decision that pays 300 of 303 actual coins. It then receives only one delivered crate, ending with fifteen coins. The centre and 111 plants survive, but the player cannot afford the minimum thirty-coin next worker. This does not justify changing game wages, yields or army pressure.

The new standalone QA candidate wraps Q14. Day-one six-worker startup, measured service gates, physical delivery probation for additional hires, native commands, constant prices and crop/task rules remain unchanged. It changes only later daily renewal allocation. Before recommending renewed staff, retain the minimum actual hiring price (thirty), the selected seed's base cost and any already-pending repair quote. Staff is bounded by the old recommendation and the actual remaining salary cash. If there is enough cash for just one worker, that emergency remains possible with an explicit reserve shortfall; no cash or contract is granted.

For the retained day-seven recommendation, Q14 chooses ten workers for 300 and leaves three. Q15 would recommend eight for 240, leaving 63; the target retained minimum is 35. This is a read-only recommendation applied to the archived command, **not** a replayed campaign or guaranteed economic recovery. The full eight-worker next payroll still costs 240 and remains unfunded; the diagnostic explicitly preserves that risk.

The policy's ordinary future recovery reserve updates only after the native hire is paid and confirmed. It does not limit plants, credit future harvests, reorder FIFO jobs, make workers faster, waive salaries or count recommendations as activity. The candidate may be less productive because it renews fewer workers; only a fresh full short campaign can determine whether it actually helps.

Four focused tests use the retained failed recommendation and explicit isolated unit fixtures. They verify unchanged original records, payable native wages/ledger receipt, state-preserving recommendations, observation after reload, unchanged Q14 at the same checkpoint, original startup/young wages, pending-repair reservation, unfunded emergency and invalid numeric inputs. Combined Q7/Q9/Q14/Q15 regression passes twenty tests. An initial test incorrectly asserted a boolean success from `Game.hire`, whose successful API returns undefined; the corrected test checks the actual paid ledger and cash instead. No production behavior was changed to satisfy that assertion.

Q15 is currently a standalone candidate, not imported into the campaign runner or approved for main. The existing live v101 Q14 pilot must finish with its original frozen sources before opt-in runner integration and new pilots. The geometry failure of the Canyon contour remains a separate required investigation; retaining cash does not certify a wall or resolve an inaccessible service pose.
