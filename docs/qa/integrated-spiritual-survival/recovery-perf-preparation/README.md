# Technical preparation for future recovery campaigns

Isolated branch `codex/raid-recovery-perf`, based on `41797669`. The live candidate-4 seed-123 campaign remains on its original worktree and loaded sources. This preparation does not restart, resume or alter that campaign.

Runtime adaptations are limited to five files: the approved PR25 fractional worker connector and cooperative search/smoothing, plus the PR26 exact watering cache. The latter remains subject to final synchronized-head CI/main acceptance. The experimental navigation `skipDirect` option is retained; the file was not replaced by main's navigation wholesale. Agricultural power, raids, pressure, reservations, crop damage, prices, salaries, wall resistance, policies and RNG recipes are unchanged.

The first 81 targeted tests pass with no skips: worker departure/reload, watering/cache, gates, navigation query scopes, pressure recovery, budgets, plans and candidate migration. Original TAP and exact source review are preserved here. Compared with the live 464-file inventory, only Game, Navigation and work-points change; two helper modules are added. Sparse-omitted unchanged files were checked against their original Git objects, so this audit must not be presented as a complete runnable/validated campaign dependency inventory.

A full managed checkout failed with ENOSPC and was automatically removed. The live PID and progressing outputs were subsequently verified. The replacement manual worktree uses sparse code/data selection and shared node_modules; about 66 MB was materialized rather than duplicating historical reports. No campaign data was deleted. Disk headroom must be checked before further large builds/checkouts.

Paired native watering checks now pass on this experimental integration. Two recorded Canyon scenes and two explicitly synthetic enclosing-solid cases preserve every serialized state for 30 ticks, including ledger/RNG. In the first blocked case A=8,059/8,009 ms and B=604/586 ms; in the second A=3,202/3,277 ms and B=243/217 ms. Ordinary reachable-case timings show warm-up variation and are not evidence of a general improvement.

The 500-crop replay completes 300 simulated seconds (3,000 ticks per arm), with every serialized tick state identical. AB/BA total native tick CPU is A=11,699 ms, B=12,261 ms, B=11,963 ms, A=12,678 ms: the pair means differ by only about 0.6%, effectively neutral in this contended run. Native path calls fall from 318 to 177, but that alone must not be sold as a whole-day speedup. The historical explicit QA funding is retained; the replay adds no money, player actions or synthetic deliveries. Original reports/stdout are archived losslessly under `paired-receipt.json`.

Both controls use the same integrated worker/navigation implementation and differ only in the watering recipe; these measurements isolate the cache, not all five technical changes against the original campaign. They are CPU diagnostics, not GPU/FPS, physical-device or full survival measurements.

The one initially omitted provenance input, `docs/qa/intensive-acceptance-policy.json`, is now materialized through an explicit sparse pattern. A new complete source manifest reads all 466 declared sources from disk: the original 464 plus the two helpers. Exact comparison confirms only the three declared existing runtime files differ. `complete-source.json.gz` and `complete-source-review.json` retain this preparation. The original strict launcher was explicitly checked and still rejects this different inventory; it has not been weakened.
