# Retirement of resolved farm entities

The previous save kept every harvested/destroyed crop and every delivered crate indefinitely. Live indexes removed much of their repeated CPU cost, but the domain and serialized snapshots still grew with lifetime harvests. The transition at each dawn now removes delivered crates and dead crops that no active crate or spell still references. A terminal military defeat performs the same retirement after its final event. This does not change cash, damage, wages, harvest timing, routes or animal decisions.

The crop behind an undelivered or dropped crate remains until that crate is settled, preserving the existing save validator and source-based delivery position. A crop targeted by an active spell remains until its effect expires. Crop/crate arrays are replaced when shortened, so the existing WeakMap live indexes and worker lookups rebuild against the new membership. Old saved games still load; their resolved entities retire at the next dawn. No save migration is performed on load.

Campaign accounting no longer treats the game arrays as a historical archive. The intensive QA runner observes confirmed crop and crate events, keeps aggregate per-species results outside `Game` and reconciles them with the financial ledger. Archived campaign reports without the new observer data retain their original historical-state analysis path. The opening QA runner similarly records watering at pickup, while delivered income is read from settled ledger entries. Tutorial completion uses a durable `harvestCompleted` flag after the delivered crate has retired; loading an older save migrates it from a delivered crate, delivery event or completed harvest lesson.

Run `node tools/benchmark-retire-farm-history.mjs 20000 500` for the isolated size case. On this host, 20,000 dead crops, 20,000 delivered crates and 500 living crops occupied 4,714,765 JSON bytes before retirement and 50,316 after it (98.93% less); two runs measured 1.95 ms and 5.4 ms for retirement. This synthetic projection is not a measured browser RSS saving or campaign-wide speedup. The previous live-scan benchmark remains in `docs/qa/live-entity-hot-paths.md`.

Validation includes the retained crate/spell save test, paid opening and intensive farming, deterministic replay, native animal terrain, tutorial, genuine neglect defeats and postgame continuation. The complete test suite passed with 4,469 tests, zero failures and 60 planned skips; `npm run build` and `npm run verify:plan` also passed. The financial ledger, command IDs and bounded event ring still keep information needed for accounting, idempotency and presentation. This change removes historical farm *entities* from the long-running domain; it does not claim that every kind of historical metadata has been eliminated.
