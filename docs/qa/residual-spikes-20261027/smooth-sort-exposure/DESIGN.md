# Translation-invariant impostor sorting experiment

Production src/rendering/smooth-far-transitions.js remains unchanged. Two isolated copies, routed only by an explicit QA environment variable, share identical instrumentation. The candidate changes only the invalidation key: instance-attribute versions plus the view depth row (2,6,10) and atlas height, instead of the whole view matrix. This matches the values actually used by the existing depth comparator. No epsilon/quantization is introduced, so genuine orientation changes and floating-point orientation differences still invalidate conservatively. Translation and uniform origin offsets add a common depth offset and do not change this comparator's order. Billboard geometry/shaders and transparency remain unchanged.

The existing baseline also misses atlas-height changes in its signature; candidate height invalidation is tested against a freshly prepared original fixture. Source attribute versions still trigger copying of all channels, including readiness; finer per-channel updates are outside this bounded experiment. Hull/index synchronization and draw/instance counts run before the cached-order early return. Ownership and disposal stay with the original scene-scoped owner.

Validation: node --test tests/smooth-sort-orientation-experiment.test.js tests/smooth-far-transitions.test.js passes six tests. Differential buffers match across 30 translations, 12 rotations, position/readiness changes and an origin-like camera shift. Translation does not increment candidate attribute versions; original does. These unit checks are not visual acceptance of live distant foliage.

Real-game run: node tools/experiments/run-smooth-sort-exposure.mjs; then node tools/experiments/compare-smooth-sort-exposure.mjs. Original/candidate routes are explicit, snapshots are taken after the 40-second traversal, simulation remains active, initial warmup reaches 30 seconds. Frozen source hashes include both experimental copies and runtime/fixture inputs. Counter totals include warmup and represent rewritten CPU attributes marked dirty, not actual driver upload measurements. A single A/B is only an exposure screen. Prior A/A variance prohibits treating small timing differences as a demonstrated optimization.

The post-traversal camera looks down at crops: it is useful for confirming the game remains present, but does not visibly cover distant impostors. Additional horizon-facing pixel comparisons and repeated interleaved performance measurements are required before production adoption. No artistic approval or whole-goal completion is claimed.
