# Regional worker payload attribution

Instrumented real Manglares game with active simulation, moving camera and 40-second streaming window. `run-regional-tail-phases.mjs` captures source hashes and stable-residency preflight; `summarize-worker-payload-shape.mjs` pairs each payload-shape record with the immediately preceding event.data getter. Run completed with no page/console errors and no dropped attribution rows.

Loading messages: 5352 tree records + 1793120 ground-buffer bytes took 19.325 and 11.905 ms synchronous event.data wall time. During the controlled stream: 5330 trees + 1792064 bytes took 10.315 ms. Tree-only messages with 474–542 records took .470–1.145 ms; 2153 records took2.000ms. Empty messages were below .1ms. These are wall times, not exclusive deserialization CPU or GPU time. This single run establishes a candidate target, not causality or an optimization result.

Source inspection finds additional structured-cloned ground metadata beyond transferable geometry: fitFarGroundContacts returns contactCells (nested triangle arrays keyed by cell) and contactAnchors (id/vertex objects). contactCells is forwarded again to the seam worker and used for exact height sampling; it cannot simply be dropped. contactAnchors has test consumers but no discovered production reader. Tree records have13 fields including a string id. The shallow metadata probe itself costs up to .580ms (.440ms on the streaming ground message), so instrumented numbers are not a clean production baseline.

Next hypothesis: encode contact topology in compact transferable typed arrays, preserve exact triangle ordering/height interpolation, and avoid reconstructing nested objects on the main thread. Measure codec/build/forwarding costs as well as whole-frame and chunk latency in interleaved runs before adoption. Do not infer that reducing payload alone solves P95/P99. Tree packing is a separate possible treatment; do not conflate both without attribution.
