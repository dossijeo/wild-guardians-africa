# First desktop integration — source review only

No build, GPU, CI, browser driver or new renderer has run. This source implements only the non-timing visual/ownership phase. Timing mode explicitly rejects; total GPU AB/BA is deferred until native visual/resource review.

## Exact integration boundaries

- `src-tauri/smoke.js`: the existing `desktop_smoke_fixture` result opts in only with `workerRenderQa.enabled === true`, before the existing load-slot action. Ordinary smoke/play has the flag false. After genuine ready/world capture, the existing tester calls the product-bound promise and exports through its original Tauri report command. It deletes the callable/flag afterwards. First reviewed configuration should be `{enabled:true, mode:'visual', limit:1}` on a fixture with a paid, active youngMale worker; no worker is fabricated if the loaded save has none.
- `WorldScene` constructor: the owner is created only at the end of successful constructor initialization and only if smoke started, the explicit flag is true, and the native Tauri invoke bridge exists. No borrowed runtime from the interactive-loading branch has been merged.
- `WorldScene.actor` adoption: after native SkeletonUtils clone, native clip assignment and **before `root.add(model)`** fires registry discovery, the selected first youngMale rig prepares material aliases. Source SHA, material association IDs and the five names are checked. Already AfricanToon-decorated source materials fail before cloning; this may reject fixtures where a previously adopted crate/worker already decorated those shared materials. It does not silently double-decorate or switch to another shader. Failed adoption releases that rig's aliases.
- `src/app/main.js` original `frame(now)`: schedules its existing next RAF and updates `lastFrame`, then exclusively delegates if the smoke owner is active. That frame returns before ordinary simulation/tutorial/save/audio work and ordinary world rendering. The probe has no RAF loop of its own. It invokes production `renderFrameUpdates(0)`, samples one native baked clip, and invokes production `drawRenderFrame()` once. Target/camera are selected before frame updates so native camera protection, render-origin, sunlight and shadow focus retain their original paths; the actual resulting camera is reported.
- `WorldScene.dispose`: releases the QA owner before original world resource disposal. The probe never disposes the world, renderer, Assets, borrowed geometry or skeletons. Its own copies are restored/released in finally and the callable is removed only when still owned by this instance.

## Clone recipe

`prepareWorkerQaMaterials` uses the audited material-only helper, with raw source hooks captured **before** decoration. The originals enter the normal SceneMaterialRegistry during native adoption. Candidate clones remain off the model until their arm; registry refresh then decorates each candidate exactly once through the same owner. Source/candidate/source cycles retain the registry WeakSet guard. Shared source materials on nonselected meshes stay untouched. Body keeps original FrontSide. The five candidate raster sides are FrontSide; shadowSide is explicitly original DoubleSide isolation or separately requested FrontSide. `DOUBLE_SIDED` is preserved explicitly for normal/TBN, so this is an additional runtime treatment, not default candidate-GLB-loader equivalence.

The prior CPU audit verifies the complete source/candidate metadata and identical binary chunk, 28-joint skin, clip/accessor/image/UV/weight data. The probe's material aliases are limited to that frozen metadata diff; no general geometry alias/export mechanism was added. Production manifests, source hashes, watering paths, tasks and 48 library actions are untouched.

## Ownership/restoration contracts

The owner holds the existing app state by exclusively bypassing normal advancement while active, then restores its temporary time, camera/controls, target/viewport/scissor/clear/shadow state, native original action and node transforms. It checks serialized state equality, geometry/attribute identity, original geometry/material disposal events and owned materials remaining. It does not equate renderer.memory to ownership or physical VRAM. It cancels on native visibility, loading/world disposal or context loss. Error/cancellation observations stay in the report. Source repeats and small image differences are diagnostic only.

Six CPU tests passed (181ms runner): native flag-off gates; 48 cases/12 clips; exactly one decoration per source/candidate with unrelated sharing preserved; already decorated/incorrect association rejection; native-hide cancellation with full restoration/owned-release; prior toggle/reinstall and invalid-source ownership contracts. Tests use real Three scene/material objects and CPU mixer primitives with a non-GPU renderer stub. They are not native appearance, GL-buffer, shadow or benchmark evidence. Four edited/new JS files pass `node --check`; CRLF-aware diff check passes.

## Limits for root review before compile/run

1. This first module supports only youngMale visual/ownership, native whole-screen original/repeat/candidate at the unchanged canvas resolution. All 48 cases can be selected, but raw full-resolution PNG per arm can make a 48-case report large; run `limit:1` first and review a bounded atlas/export strategy before a full campaign. No timer queries yet.
2. The default existing smoke fixture may not contain a youngMale actor. The probe fails clearly rather than importing another renderer or injecting an invented actor. Fixture preparation must use the existing product save/paid-worker mechanism in a later reviewed step.
3. The clip override is a directed baked-clip inspection after native updates. It does not prove task reachability, physical watering/crate delivery, continuous motion, all four profiles or source-normal repairs.
4. Material sides are currently reported metadata; actual color GL cull, shadow/depth draw witnesses and buffer-size readbacks remain native resource-phase work. No hardware acceptance is claimed by CPU tests.
5. Production depth runs only when the original VFX preparation asks for it. The first representative fixture may have no actual depth draw; do not infer depth correctness from color. No synthetic depth pass or shader has been added.
6. Pending review: constructor/adoption/RAF hooks and clone recipe above. Do not compile, execute GPU/CI or promote assets until root accepts this source integration.
