Ground probe borrows the world renderer/materials, restores its temporary state and disposes its owned offscreen resources. It does not create another renderer/window. This is a pattern to extend inside the existing product tester; none of those branch files have been imported or modified here.

The current worker browser harness is **not portable as-is**: it constructs a private renderer, sky, scene and asset owner. Reuse its case definition, diagnostic policy and audited five-mesh material selection only. Do not open that browser page in a native window as a substitute for the original product scene. Do not use Playwright, CDP, custom browser automation, a helper executable, or the smoke capability canvas for worker QA.

## Candidate aliases and shader fidelity

This pilot is strictly **metadata-only**. Source youngMale SHA is `25e4ab988c87419007f185c956970b3329e7379e9fab4bcbe6851cb1e81de238`; candidate SHA is `3ac771a241023c3ec68df0ffdaeeb4d9c83f6380b4205a5000b17f751c15f2c7`. The candidate has an identical complete binary chunk, nodes, skin, animation/accessor/image/texture data and original materials. Its only GLB differences are five appended material clones with `doubleSided=false` and primitive material references for crate 7/8/9 and hoe 23/24. Five source material IDs are 5/6/7/2/3 respectively. This is 8,640 triangles with +1,532 JSON bytes and no extra geometry/groups. It does not authorize a generic geometry-repair alias mechanism.

Before enabling the aliases, validate the frozen source SHA, exact selected node/primitive/material IDs and material diff, plus expected geometry/rig/clip fingerprints. Aliases borrow the already loaded native geometry, textures, skeleton and animation payloads; only selected material clones are owned by QA. Body Mesh0 remains its original FrontSide, every other accessory remains its original sidedness. Do not force the body to DoubleSide to create an artificial benchmark gain. The existing watering-path manifest source SHA and all pose/task durations remain original.

Raster FrontSide plus preserved `DOUBLE_SIDED` normal/TBN is the **explicit runtime recipe**, not an assertion that default GLTFLoader rendering of the candidate file is identical. It must preserve the existing native compile hook/cache-key/uniform recipes. Already decorated source materials must not be decorated twice when a clone enters the registry. Either create the aliases before the original first adoption/registry decoration, or use a reviewed exact hook-preserving clone and mark it as already decorated for that specific toon owner. Fail on an unsupported compile recipe; do not silently use StandardMaterial-only shaders. Material-ID mapping must isolate shared source materials so that unrelated can/fruit/sack meshes keep their original policy.

## Native visual/functional campaign

Use the **actual ready WorldScene.renderer**, screen target and stage dimensions. Record canvas pixels/CSS size, pixel ratio, quality, renderer/context attributes, render-origin, camera matrices, sun/shadow configuration and source programs. No fixed 512px replacement context. Capture on the ordinary screen output; an offscreen target would be a separately labelled diagnostic with possibly different program/output recipe, not screen equivalence.

First representative profile is youngMale, with the existing 48 cases: 12 clips × two normalized fractions × day/night, across predefined camera azimuth/elevation. Other profiles have source-only compatibility inventory now; adapting all four remains later scope. Direct clip sampling through the production fixed-pose path covers baked clips including Wave/Hit/Fall, but does not by itself prove every Game task reaches those poses. Watering/nozzle, crate attachment/visibility and physical task behavior remain separate functional evidence.

Prefer resident native actor rigs and original material/geometry references. If a controlled layout needs additional actors, use native actor adoption/ownership and label it a QA arrangement; never mutate a campaign save to pretend it naturally contains those actors. Preserve the original world/save object, workers/tasks/RNG/clock, active clip state, node visibility/transforms, camera/controls, registry and original pause set. The test scheduler must use the existing app RAF with one authoritative draw. A named QA pause may hold simulation only during the directed test, then remove only that pause; menu/hidden pauses stay intact. Restore fixed poses using their original runtime worker/state inputs before resuming, not by rebuilding a world on the same lost canvas.

Capture original, original repeat and candidate stills/atlases with raw diagnostic differences retained. Inspection prioritizes recognizable worker/body/tools, convincing motion and no perceptible missing/deformed parts. Pixel/color/small-hole numbers never automatically reject. Record exact program/cull/front-face and shadow-depth draw witnesses in this **non-timing** campaign. Include clip, fraction, native elapsed, instance/node transforms, bone palette and whether selected tools actually draw. Empty selected draw coverage is inconclusive, not approval.

Shadow policies are distinct: first preserve the selected original DoubleSide shadow policy while isolating color; then evaluate selected FrontSide shadows separately. Nonselected and body defaults stay unchanged. World VFX depth is only exercised when the original production pass actually requests it. No invented depth shader, unconditional extra capture or assumption that color/shadow/depth use identical materials. Worker skinning and rigid attachments must remain part of the actual passes.

## Resources, restoration and export

Non-timing resource phase records original and coexistence handle counts, owned material/program/texture/buffer changes, and queried buffer sizes where supported. Geometry/attribute/index/textures are borrowed; their identity and disposal ownership must survive source/candidate/source cycles and release/reinstall. No geometry dispose or buffer deletion is permitted for borrowed originals. Only QA clones, targets if explicitly diagnostic, queries and listeners are released. Renderer.memory is diagnostic, not ownership proof or physical VRAM.

Snapshot renderer target/cube face/mip level, viewport/scissor, clear state, autoClear, shadow state, animation state and callbacks; restore in finally with every restoration attempted even after an earlier error. Abort on world replacement/disposal, native hide, cancelled loading, context loss or shader error. Keep the original negative report, cancellation cause and incomplete coverage. Product exit/WorldScene disposal remains the original owner; the probe must not dispose that renderer/world/Assets. Compare serialized world/save and native rig/geometry identities before/after at the held-state boundary. Export through the existing Tauri report command, retaining warnings separately from errors and immutable run IDs/hashes.

## Net GPU phase (after visual/resources review)

Prepare frozen AB/BA blocks of **the same ready world**, original effective sides versus the five material aliases, same worker poses/counts/attachments, camera, sun, resolution, quality, far isolation, VFX state and background. Include all groups and original native shadows. Warm/compile both recipes outside measured samples, record warmup count prospectively; no rerolls that erase negatives. Dense controlled worker layouts are QA fixtures, not naturally successful saves. Report net world and scope; no crop gain inheritance.

Separate total envelopes and per-pass campaigns because WebGL TIME_ELAPSED queries cannot nest. Total includes the ordinary complete draw sequence. Phase instrumentation can bracket only actual existing depth capture, native shadow render and main color draw without changing draw order or adding draws. A main color renderer.render normally includes shadow rendering: unless a reviewed boundary separates it, label it **color+shadow**, not color-exclusive. Sky, destruction prepass/smoke and any residual work must be accounted for, not silently subtracted. If robust phase isolation is unavailable, total net GPU plus honest available phase scopes is sufficient evidence; do not invent split timings.

Query polling/availability happens outside active envelopes; no fingerprints, getBufferSubData, readPixels, resource queries, PNG encoding, console serialization, save writes or compile/warm work inside timing. Record supported/reason, valid/pending/disjoint/discarded/foreign-query/overflow/unresolved and query cleanup. Unsupported EXT means visual/resources evidence only and GPU benefit pending. Frame/CPU timings are not a substitute. Present paired block medians/dispersion/outliers and raw samples; improvement must be sufficient and consistent against the current original body-Front recipe before any activation/PR.
