# Optional physical agricultural impact candidate

Base: `ef2222cd282bb8a6297ebaeeb7dd5bf8609e5498` (reviewed FIFO candidate). This commit does not attach profiles to raids or activate the future pressure scheduler. Legacy actors without a profile retain their existing attacks. No campaign, GPU, visual acceptance or balance claim.

## Geometry and facts

The central impact is the selected crop position in X/Z. The actor must stand on a native valid full-radius footprint, within radius + 0.65 m of contact (native approach uses radius + 0.6 m), and face the contact within 45 degrees. Existing actor motion, collision, approach and attack timing remain authoritative; this module never moves an actor. Peripheral candidates lie in the forward 90-degree sector centred on that contact and within the configured radius. Central damage is full; peripheral damage is half. Central is considered first, then closest crops with deterministic ID ties. Only positive effective hits count toward areaCap.

Native wall polygons (including animal-blocking gates), centre footprints and house footprints/circles obstruct actor-to-impact, actor-to-crop and impact-to-crop rays. A collapsing solid still obstructs; a ruined one does not. Shield circles obstruct each ray and protect endpoints independently. Terrain water/lava is not a wall; native actor navigation remains unchanged. This is conservative 2D geometric occlusion, not a height-aware weapon-socket ray or a GPU mesh raycast. Crops cannot be damaged through a wall by a crop strike, and structural strikes have no crop splash.

Each actor persists a bounded list of completed area attack IDs (maximum 64), in addition to existing hitApplied. Duplicate IDs cannot deal damage again after replay/reload. Crop HP remains two; exact half-points are save-valid, other fractions are rejected. Effective damage clamps to remaining HP. Once an introductory destruction quota is exhausted, remaining plants can only be wounded up to one point, including a requested damage of four. No incomes, crop growth, task queues, RNG, or budgets are synthesized.

Profile validation uses current canonical limits: cropDamage integer 0..4; structureDamage integer 0..90; radius 0..3.640001 m (epsilon for calculated 3.64); areaCap integer 1..7; peripheralWeight exactly .5 if specified (omitted defaults to .5). Unknown profile keys are rejected. This is a persistible optional descriptor; root must attach descriptors produced by the canonical species/pressure planner, not arbitrary high-cap save data.

CropHit includes targetId, attackId, animalId, central, requestedDamage, damage (effective), before, after, hits=after and destroyed. One existing AnimalLogicalHit contains agriculturalImpact (point, heading, radius, sectorDegrees and the same hit facts), also in its existing presentation. A physical rejected contact emits one AnimalLogicalMiss; central Shield retains the native single consumed logical hit with blocked='shield' and zero crop damage. No additional VFX/SFX event or RNG draw is introduced. Existing presentation target coordinates match the central impact point.

## Query lifecycle and bounds

A WeakMap keyed by the crop save array owns a 2 m spatial grid. First use/topology version change builds from active living crops, append is incremental, local queries discard dead bucket entries, and restored arrays receive fresh caches. Crops are stationary in gameplay. An editor that changes positions must call invalidateAgriculturalIndex or native nav.setState; in-place array membership changes must obey active-crops invalidation as elsewhere in the engine. No whole-farm fingerprint or historical-array scan is repeated for every hit.

Only cells intersecting the radius <=3.64 bounding square are queried (at most 25 cells at 2 m); work within those cells depends on local density, not distant farm population. Candidate sorting is local O(k log k); maximum applied plants is seven. Solids have a separate topology/obstacle-identity grid, queried over each short physical ray. Oversized footprints spanning more than 4096 cells enter a conservative overflow list rather than allocating unbounded cells. Shield checks inspect the active spell list. These are complexity bounds, not a frame-time guarantee; dense overlapping malformed crops or many enormous solids can still increase local work.
