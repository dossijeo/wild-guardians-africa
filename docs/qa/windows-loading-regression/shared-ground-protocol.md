# Shared Basic ground color — native candidate protocol

The packaged executable is identical for two consecutive invocations on one Windows runner. The diagnostic control runs first with shared ground OFF; its failure and report are preserved. The candidate runs with `--smoke-shared-ground`, then the original native minimization/restoration smoke. Dispatch defaults to false; ordinary play stays unchanged. Collective readiness and parallel diorama asset experiments are OFF in both invocations. CPU budget, resources, all program readiness checks, owner cancellation and the original 90-second world gate remain intact.

Only Basic biome ground color shaders share the resident/horizon recipe. Each material retains its own bounds uniform; resident bounds are zero, horizon clipping uses the existing half-open rectangle. Depth recipes remain separate. Tests exercise actual Three uniform uploads and mock-renderer ownership/restoration faults; they do not establish native raster correctness.

After genuine world readiness, a smoke-only 4×4 target (16 pixels) probes borrowed resident/horizon materials in alternating order, checks clipped and moved bounds, records screen/offscreen program identities, and restores bounds and renderer state. Its offscreen recipe may differ from the screen variant; this is explicitly a raster binding check, not proof of screen program identity. The readiness timestamp precedes this probe. No borrowed material is disposed. If the world never becomes ready the probe is not reached and cannot pass by proxy.

Record both raw reports, config/seed identities, asset spans, pending programs, raster results, original smoke outcomes, executable and installer sizes. Order/cache and random New-game seeds can differ, so timings alone do not prove causal savings. Nested awaited spans overlap and must not be summed as exclusive CPU/GPU work. Promotion requires both original candidate smokes and the native binding check to pass; retain all previous failures. No timeout is extended.
