# Contiguous wall buffers: isolated OFF candidate

The 24b original native failure stopped before compilation with 56 pending binary fetches after crops. Source identifies the required wall stage as 100 base buffers, then 60 morph buffers. This candidate reduces that stage's binary requests from 160 unique URLs to one; no timing benefit is established by CPU tests.

`tools/prepare_wall_buffer_package.mjs` walks the original descriptor insertion order: each piece p/n/uv/index/faceRegions, then every morph p/n. It preserves every payload byte and appends zero padding to align every lane to four bytes. Payload sum is 5,135,408 bytes; package is 5,135,464 bytes (56 bytes padding), SHA256 `342e2abd04f9594cdeb2003f00f313f8d91b44b28d44f17ea9901ec1dc84883d`. The wall texture is separate and unchanged. No compression, quantization, vertex reorder or subset/lazy loading occurs.

The manifest records URL, field path, f32/u16 type, offset, length and individual SHA256, plus original descriptor SHA. The runtime validates descriptor encoding, URL/type membership, complete package length and aligned bounded ranges before adoption. It returns bounded byte views into one buffer, and the original geometry/morph constructors use aligned typed views, without copying the full package per lane. All20 prototypes, bounds, regions, peers, shadow/material settings and morph dimensions are compared against actual Assets.walls legacy results. Offline tests verify all160 exact hashes; runtime does not add hash/decode work.

Texture remains first. Same Assets.preparation signal controls the single original bytes() loader. Assertions occur after package arrival and before each lane/prototype adoption. A late buffer after owner disposal produces no geometry; a late texture is disposed exactly once. The buffer itself is CPU memory managed by typed-array reachability, not a GPU resource. Existing geometry/material disposal remains the owner path; no package cache or new renderer is introduced.

Normal gameplay/default remains160 requests. Opt-in requires both smokeStarted and smokeWallBufferPackage literal true; there is no CLI/workflow wiring yet. The future isolated comparison requires compile_window=false/resource_overlap=false and all historical hypotheses OFF. Original90s, full material variants, depth/readiness/fences and scene stage order remain unchanged. No Rust/protocol/cache/sky/compiler change is made.

Shared-use scan finds all160 URLs both in `public/content/walls.json` and the actual wall library `public/library/walls/bastion-assets.json`. Originals are preserved. The diagnostic package deliberately adds one5.135MB asset; build totals rise from711/445,275,241 bytes to712/450,452,640 bytes (delta5,177,399 including bundled descriptor/code). It is not a production-weight improvement. Before any future promotion/removal, the library loader must also safely support packaged descriptors (or a documented separate archive boundary), otherwise deleting originals breaks library previews. No deletion is performed now. There is modest static manifest/code overhead even with the experiment OFF.
