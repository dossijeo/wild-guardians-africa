## Existing native route and provenance

The bb1 executable already accepts `--smoke-report PATH --smoke-visual --smoke-fixture PATH`. Rust sets the visual boolean before the original smoke invokes the existing load-slot handler. The fixture is imported into its isolated native profile under its own slot; smoke keeps its original readiness and visibility gates. App installs the read-only LoadingVisualQa owner; the original diorama render calls its collector after drawing and restoring screen/shadow state. Native finish exports checks.loadingVisual.frames, each actualcanvas PNG with plant coordinates/growth, night coefficient, progress, camera and dimensions. Root's c0e14931 Python extractor validates PNG CRC/dimensions/labels/limits and writes new files without overwrites. These canvas images do not contain the HTML HUD; capture/readback overhead prevents timing conclusions.

Use two individually hashed, owned fixture records with seed712, gran-canon/Mapungubwe and legal paid planting. Reuse the commands and terrain/navigation provenance in tools/create_desktop_visibility_fixture.mjs / tools/check_opening.mjs: Game.placeStructure, reachable Game.plant('yuca'), Game.openInitialHiring and Game.hire, then Game.tick for progression. Save one day record while skyNight(state) is0, and one night record only after normal Game.tick yields skyNight(state)>=.99. Do not assign time/elapsed/day/growth/RNG/balance, inject save maize, force raids or clear events. If legal progression cannot produce a live crop-bearing night record, retain that failure and use an existing consented real night save rather than manufacture it. Record source hashes, command/event log, seed, terrainVersion, snapshot SHA/bytes, day/time, paid crop IDs/species/alive/growth, money and camera provenance. Freeze each serialized snapshot before native import. The existing visibility fixture pays for cassava and a worker; it is not a plant-free save.

Separate visual invocations per fixture/profile/report are proposed for review, not launched here. Use real landscape and portrait native window sizes, recording actual drawing dimensions; never resize midway and call an incomplete capture valid. Initial diorama frames must show four actual private loading-maize plants with canonical textures, and night coefficient must match the real fixture clock. Middle/mature captures are opportunistic on existing draws; no sleep or extra frame may be added to guarantee them, and missed phases remain missing. A final-world canvas screenshot must visibly contain the fixture's real paid cassava; canyon-only scenery is insufficient. Camera fit/occlusion can be checked by projecting the actual crop on the ordinary camera; if it is offscreen, explicitly report missing coverage rather than insert new crops or alter a saved pose silently.

## Optional fifth plant: proposed narrow hunks

Add a separately guarded `--smoke-visual-plant` option, requiring both --smoke-report and --smoke-visual. Rust may set one boolean __desktopSmokeVisualPlant; App creates an owned action helper only when both visual booleans are true. Ordinary gameplay and ordinary smoke do not install it. The global export stays read-only {report}; it must not expose World, diorama, methods or closures. No PointerEvent, isTrusted assertion, setPointerCapture override, UI automation fallback or simulation command is involved.

Proposed new src/app/loading-visual-plant-qa.js receives the current diorama and the existing collector. Its afterDraw handler runs only after the collector successfully records initial with exactly four plants. Preconditions: same owner/generation, prepared, interactive, accepting, not disposed/aborted, canvas rect/drawing size valid, not cinematic and progress<1. Mark attempted BEFORE the call to prevent retries on reentrancy/error. If the eligible draw never occurs, close records skipped with reason; do not delay readiness/cinematic. The action occurs after the initial readback, so the fifth plant is updated/drawn naturally on a subsequent existing frame; collector additional-plant is the pixel evidence, not an immediate count-only claim.

Point selection is deterministic and read-only. Enumerate at most12 candidate ground points on a radius3.4 circle inside LoadingPlants.radius4.3; reject candidates within actual spacing1.5 of any existing plant. Project each point using the current diorama camera and actual ground matrix, convert NDC to the current canvas client rect, and require finite coordinates inside the canvas with a small margin. Verify the point with the same real Raycaster/ground intersection and the real radius/spacing predicates; this is selection, not insertion. Record bounded attempted/eligible count, chosen client coordinate, projected ground coordinate and pose. Call `diorama.plantAt(clientX,clientY)` EXACTLY ONCE for the selected point. That method recalculates its ray using current matrices and invokes existing LoadingPlants.plant and onPlant/SFX. A null return is a failure, not permission to bypass spacing or write plants.push. If there is no safe point, record skipped. Do not use a fixed screenshot coordinate across orbit/aspect changes.

The action report explicitly labels `synthetic engine-handler raycast; not physical/trusted input`. Record four->five count, returned loading-maize ID, accepted x/z, growth at insertion, onPlant result if already exposed, and eventual captured fifth plant growth. Record state.plants array identity/count/IDs before and immediately after action, and isolated tests require the entire representative logical state/save unchanged. Do not claim arbitrary snapshot equivalence from those scalars alone. LoadingPlants is private presentation state; never call Game.plant, World crop batch insertion or save writes. A genuine additional-plant PNG and eventual private catch-up are needed for visual acceptance; mocked PNG or count-only tests are insufficient.

## Ownership and validation before implementation/native approval

Compose the action after existing readonly collector, not as a replacement. Keep one generation-owned helper and one attempted action. On cancel, complete, dispose or replacement remove callbacks/listeners by identity and clear strong world/diorama refs. Old callbacks cannot act or replace a newer owner's data; failures are bounded report entries and cannot break rendering/readiness. Constructor/flag/point-selection faults are observed once. No global retained action API, new renderer, RAF, timers, resource requests or progress manipulation.

CPU tests proposed: both required guards/defaultOFF; actual LoadingDiorama.plantAt with THREE camera/ray/real ground geometry for day/night and landscape/portrait; exactly-once action plus real onPlant callback; no safe point/null hit/occupied spacing/no retry; raycast changes under orbit or resize; cancel before selection, cancel/replacement before nextdraw, error and late callback ownership; no mutation to logical state/persisted fixture; collector initial then additional-plant on the next real draw; closure and bounded report. These tests establish callpaths/lifetime, not image raster or physical input. Then root reviews diff/build/package/SFX fingerprints before authorizing any native artifact inspection. Native reports/PNGs/config/fixture hashes and original gate failures must all be preserved.
