# Next investigation, not an implemented optimization

The measured terrain memoization is rejected. Its subsequent safety correction captures immutable native method references at module import, invalidates previously canonical leases if those prototypes change, and bypasses altered adapters. Eleven directed tests pass; that source is a separately hashed, unmeasured version, still OFF. The measured archive remains byte-exact.

The existing service proof visits 32 attack poses per target. It tests body/contact validity, a direct route, then `approachPath(outside, point, radius, 32)` before consulting complete native closed regions. `approachPath` reverses its search: the attack point is the origin. Native `findPathSteps` already checks cached exhausted components, but only after endpoint/direct tests and reconstructing all nine origin connectors. Thus sharing an exhausted-component certificate may avoid repeated origin work; it is not automatically a new reduction in A* searches.

A candidate shortcut must certify **every usable native origin connector**, including actual body-width segment checks, against one or more complete regions. It must also prove the exterior endpoint cannot connect to those regions using the same destination-neighborhood rule as `findPathSteps`. Mere membership of the attack point, an enclosed polygon, a bounded failed search, or an empty origin frontier is insufficient. Keep the original direct-route check, target ordering, 32-angle ordering, contact ray, failure reason, pose counts and physical-connector fallback. Unknown, incomplete or boundary-touching components always use ordinary navigation.

Exact equivalence additionally requires honoring the native `path` ordering: failed-path keys, prepared results, private navigation-query results, then the search. Prepared paths and query-cache ownership cannot be replaced by geometric assumptions. A skipped failed search normally writes a failed-path key; retaining that memoization and later cache behavior matters for subsequent proofs. Any helper must share native logic rather than introduce a subtly different reachability algorithm.

The safe next step is bounded instrumented unit fixtures that count actual `findPathSteps` calls, connector queries, certificate hits and fallback reasons, with the unchanged service proof as reference. Include open direct route, open detour, multiple components, no origin connectors, incomplete/boundary searches, epoch/obstacle changes and prepared/query-cache priority. Compare entire service reports and serialized states. Only a demonstrated simple reduction justifies another short replay; no additional campaign or large benchmark is authorized by this document. The original profile and negative AB/BA provide no independent cost attribution to key/lookup versus eviction, so that attribution must not be invented.
