# Fixed derivative: prospective appearance and growth review

Policy3 applies: pixel, silhouette and small-hole measurements are diagnostic. The original `.5` geometry and forward/back material recipe are fixed; these views do not select or alter faces. No reviewer decision, category approval or GPU improvement is inferred from a numerical result.

The fixture accepts `?limit=1&caseIndex=N`. Cases are fixed in `tools/lib/frontside-shared-leaf-review-cases.mjs`: 0 retains the archived first training view; 1–3 show another daytime angle, night and dawn in Gran Río, Volcanes and Manglares. Cases 4–9 use one fixed camera/light/clock on either side of the final native bridge: preceding stage, bridge start/middle/end, first derived mature mesh and later growth. Save each report and four-arm image under a separate case identity before the next export. Inspect recognizable leaves/cobs/form, growth continuity, lighting and perceptible defects; record observations without automatically converting diagnostic failures into rejection or approval.

The actual CPU source batch audit passes all ten phase/coverage assertions. Four mature views and cases 8/9 activate the changed mesh; cases 4–7 use original preceding/bridge geometry. Consequently a bridge-only matching image does not validate the derivative. In particular, a perceptible switch at the bridge exit remains possible and needs a continuous gameplay inspection; this static plan alone cannot certify it. Live `iGrowth` is shared in all cases. Temporary CPU loader texture omission does not validate shader/material appearance.

The native fixture records effective shadow draw witnesses and the native shadow uniform, while shadowSide/customDepth remain Double in this isolation. These witnesses establish submitted paths, not shadow fidelity or timing. ShadowFront and real gameplay remain separate work. Renderer.info values describe the color pass, not aggregate full-scene GPU work.

Resource audit: 250488 nominal standalone geometry bytes versus 317066 original; 567554 bytes when both coexist. 4932 triangles versus 4935 original. Three separate draws have unique-index lower bounds 3610/3293/3293 (10196 total) versus 8983 in the source draw, so the smaller vertex allocation does not imply fewer shader invocations. Illustrative reset-per-draw LRU16/32/64 simulations give 13666/12785/11861 candidate cache misses versus 14433/14149/13589 original. Neither cache simulation nor unique bounds are measured GPU invocations. Actual resident memory, full category/web payload, shadows/draw overhead and net paired GPU performance remain pending; no original forced-Front saving is inherited.

Reproduce CPU coverage with `node tools/frontside_shared_leaf_phase_audit.mjs`; resource accounting with `node tools/frontside_leaf_shared_reverse_budget.mjs`. Originals and immutable Blender archive remain unchanged. Reports retain SHA256 identities and limitations.
