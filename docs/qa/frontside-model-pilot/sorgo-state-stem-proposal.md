# Sorgo native states: partial FrontSide investigation

The original Sorgo stem's18 simple regional boundary cycles are attachments to other drivers, not whole-model holes. Capping them would add internal surfaces; that proposal is rejected. Twelve actual stem boundary edges and other junctions remain unresolved. Closedness of a regional cut is not required universally, and these observations do not approve its sidedness.

This new conservative partial candidate tests the original indexed Sorgo native states with driver1 in FrontSide and the original DOUBLE_SIDED normal/TBN shader recipe retained. All original soil and leaf regions remain DoubleSide. **ALL original procedural bridges remain DoubleSide with original geometry, attributes, material and shader**. No source triangles, PN/UV attributes, face labels, growth metadata or original models change. No cap, vertex, reversed face or selection from an image/view is added. No original is replaced and activation remains opt-in QA.

Four arms separate original, indexed control, grouped native-state DoubleSide control, and native-state stem FrontSide. Only Sorgo native-state index order/groups differ in arms2/3; every original face appears exactly once. Other species and ALL bridge objects in those two arms remain original. The grouped DoubleSide control must preserve the original image before interpreting the culling arm. Existing native material hook, atlas, growth/wind attributes and source shadow recipe are retained. Target mature state CPU contracts are captured per arm, including attributes, bounds, materials and live instances.

Triangle and attribute inflation is zero. Mature Sorgo selects428 of6396 native-state triangles (6.69% by submissions, not projected area or predicted savings);5968 remain DoubleSide. The static state has at most two material index groups instead of one, with corresponding color/shadow draw-call overhead. New private state index arrays are owned separately; original attributes/live instance buffers are borrowed. Real per-state/category byte estimates, retained source/cache allocations, bridge buffers, effective draw/shadow counts, GPU memory and net GPU time must be reported before extending the candidate. No vertex or fragment saving is assumed, and indexing cannot be counted as a culling benefit.

The uncompressed source audit counts13097 mature-state vertices. A raw POSITION/NORMAL/UV Float32 plus UInt16 index estimate is457480 bytes (419104 attributes +38376 indices). Retaining the previous private batch index while adding the grouped index gives495856 bytes, **+8.389%**, before shared instances/material/program/cache overhead. This is an estimate from original source counts, not a claim about the decoded web model, category, GPU residency, peak scratch memory or compressed bytes. The native runtime resource/CPU contract receipt must establish its actual counts; the unchanged +10% decoded-byte/+5% GPU-memory gates still apply. No web GLB is exported, so original web download bytes are unchanged in this QA design.
