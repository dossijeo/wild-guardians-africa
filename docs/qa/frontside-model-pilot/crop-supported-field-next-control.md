# Source field control before derived rendering

This route retains the original position, normal and UV corner identity in immutable runtime arrays. A coarser leaf proxy carries a separate source-defined disk coordinate. It does not replace the authored UV atlas. Unsupported leaves, stems and soil remain the original geometry with DoubleSide materials. This is an experimental partial adaptation, not a category approval.

The supported source contains 1872 triangles in 71 charts. Its proxy has 1182 triangles and 1009 vertices. The original fallback has 3063 triangles. A hypothetical two-sided geometric proxy would therefore submit 5427 triangles, versus 4935 originally (+9.9696%). This only passes the count filter; no complete reversed mesh or candidate shader has been rendered.

The actual padded lookup textures contain 261120 bytes. The complete auxiliary binary contains 367932 bytes, SHA256 `1046256f5f432fe479e62a563e5bcb38225f6e9f453c1e03e34b48cbdeab9233`. Source position/normal/UV data textures would borrow the existing CPU arrays, but add 287456 bytes of GPU texels. Thus these tables and source fields alone add 548576 nominal GPU texel bytes before proxy VBOs, fine control buffers, driver allocation, or retained original buffers. CPU borrowing does not remove the existing source VBO. Category-wide and resident GPU budgets remain pending; the triangle result cannot waive them.

`frontside_verify_supported_field.mjs` checks whole and per-span hashes, padded texture layouts, the complete source/fallback face partition, original GLB accessor bits, source vertex references, positive source/proxy domain triangles, centroid candidate coverage, finite generated geometry and unchanged original attributes. It creates CPU geometries only. The first verifier invocation used an incorrect [-1,1] grid convention and failed; the actual packer's disk coordinates use [0,1]. Correcting the verifier convention produced a pass. Neither run invoked a renderer.

The next native TRAINING fixture must test the field recipe on the fine original geometry before testing the proxy. Its prospective sequence is: repeated original controls; original indexed DoubleSide; fine original field with explicit primitive ID/barycentrics; fine original field with disk/grid lookup; coarse field DoubleSide. The first two field arms distinguish shading reconstruction from lookup precision. The coarse arm is allowed only after both fine controls meet the unchanged visual gates. Failure stops the sequence; a result from this training view is not independent acceptance. No new heldout profile will be used to tune geometry from the rejected 104-case profile.

The shader must reproduce native growth before per-vertex normal normalization, preserve instance rotation and translation, and interpolate the source normal and authored UV. It must reconstruct the original primitive-local UV and view-position gradients for normal-map TBN/LOD, and the original primitive-local normalized-normal differences used by geometric roughness. Sampling a smooth field and differentiating across source face switches is not equivalent. Original model transforms, wind and material hooks remain part of the comparison. Failed source lookup must be observable and reported, not replaced silently with a nearby triangle.

The geometry helper currently supplies placeholder proxy normals and UVs. They must not be rendered using an unmodified original material. No field shader, native/bridge transition behavior, shadow comparison, visual approval, net GPU benchmark, or production activation exists yet. Physical reverses and FrontSide follow only after DoubleSide quality succeeds. The already rejected reductions and partial FrontSide profiles remain rejected.
