# Source color texels: diagnostic only

The preceding worker source GPU-input screen observed identical source VBO/index fingerprints and a matching finite bone texture while redraws still changed up to21 bytes/7 RGB pixels. Same-framebuffer repeated reads were exact. That screen did not observe actual GPU texels of material/normal/environment maps or depth, and did not identify a cause. The original invalid multiview sample remains invalid; no candidate was compared.

The new `sourceColorTexels` flag requires the complete source-only `sourceTwin&controlDiagnosis&sourceStateAudit&sourceGpuInputs&noShadows&limit=1` guard. It only instruments the original Mesh0, which already uses FrontSide. Candidate adaptation or GPU benchmarking cannot use this flag. Source pose/geometry/material/shader and original30 repeats/12 same-framebuffer reads are retained; no thresholds change and no favorable repeat is selected.

At each original Mesh0 after-color-draw callback the instrument resolves a sampler's material uniform Texture object, verifies that its renderer GL object is the actually bound sampler texture, and attaches it to a private READ framebuffer. It reads ordinary readable color2D expected mip rectangles using the implementation-supported RGBA byte/float read pair. Dimensions and expected mip count come from CPU texture generation/manual metadata; they are not a GPU storage-extent query. Each successful rectangle stores a diagnostic FNV32 fingerprint; incomplete, mismatched, unsupported and over-budget reads remain explicit, never equality. Depth comparison samplers are explicitly not read. No illegal DEPTH_COMPONENT readPixels, source texture upload, sampler change or comparison-mode mutation is attempted.

The helper restores READ framebuffer, readBuffer, active texture unit, pixel-pack buffer and packing state in a finally block; the draw framebuffer, original texture parameters/program/VAO and source geometry are untouched. Readback is bounded to16MiB per sampler, uses transient memory, and may perturb scheduling/timing. FNV is not collision-free. The helper's mock fault-injection contract verifies restoration after a supported read, incomplete attachment and thrown read; it is not real WebGL support or texel validation.

The native outcome must distinguish fully observed expected color levels, partial/unobserved inputs, finite/nonfinite float values, source repeat differences and same-framebuffer stability. Matching observed texels would narrow the diagnostic scope without proving a cause, excluding depth or approving any worker model. Source control gates remain unchanged. The old noShadows warning and shader branch investigations remain separate evidence.
