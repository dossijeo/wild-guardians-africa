# Three automatic maize pickup/delivery cycles

Run `node tools/frontside_maize_harvest_cycles.mjs` for the separate CPU task lifecycle witness. Retained report: `../maize-world-harvest-cycles.json` includes444 ticks of physical worker positions, three distinct planted source IDs/crates, carrying checkpoints, save hashes and three one-time deliveries. Actual Game.plant/hire/tick/rebuildTasks and serialize/deserialize APIs are used. No Game.harvest/manual harvest command is issued: maturity must emit exactly one automatic HarvestRequested per plant. Income must remain unchanged at pickup and increase only after physical delivery; later rebuild/tick must not pay twice.

Each plant begins at an explicit watered near-maturity biological checkpoint. This does not establish worker-grown five-stage continuity. Navigation is a clear-path CPU fixture; native terrain route validity, rendered worker rig/12 clips, GPU deformation and candidate appearance are independent. The simulation has no model geometry, so this witness cannot alone approve the derived asset. Earlier actual batch30-fraction and64→128 capacity tests cover stage/bridge dispatch and live lanes separately, while native893 covers changing mature color/depth uploads.
