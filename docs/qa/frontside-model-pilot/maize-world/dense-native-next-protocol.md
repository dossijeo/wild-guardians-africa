# Dense native World GPU protocol preparation

The archived World contains only 18 mature maize plants among many other crops. A small adaptation can pay six extra whole-frame submissions without producing measurable net improvement in that sparse maize workload. The isolated 1089-plant result is valid for its own graph and cannot be inherited by WorldScene.

After the original/indexed DoubleSide bridge control is convincing, create an explicitly named dense QA copy of the archived World. Preserve the original archive, terrain, buildings, worker/animal state, source IDs, positions and rotations. Change the copy's alive crop species/growth to a declared native mature maize workload, using the real cropSpec duration. Record the exact changed count, original species distribution and before/after logical hashes. Do not write user saves or claim this copy is a naturally achieved or profitable campaign. If alternative generated placement is needed, declare it as a separate scenario rather than presenting invented coordinates as the archived farm.

Both arms must share the same copy, native `createCropBatch` behavior, matrices, instance counts, growth attributes, seed/wind inputs, camera and terrain sampling. The source arm retains its native original geometry/material/depth/shadow recipe; the candidate uses the same three-group mature leaf adapter tested in its own scope. Keep all other crop states and bridges original. Source controls must remain intact, and functional input/binding probes run separately from timing.

Use WorldScene's real render graph, including Sky, colour, shadow and active VFX/world depth when that scenario requests it. Run two separately named pairs: production material-array depth handling disabled for both arms, and QA material-array handling enabled for both arms with authored candidate depth. Do not compare original depth-off to candidate depth-on and attribute all savings to maize; the global option can affect unrelated grouped objects.

Before freezing a timing source, merge current origin/main into this isolated branch after active fixture captures have closed, preserving prior receipts and resolving changes to actual World contracts. A new graph requires new measurements. Warm both actual arms and pass variants, wait for expected source/actor/texture preparation, fix viewport and camera, and freeze all imported sources. Record actual material/depth/shadow draws and counts in a separate functional/resource campaign.

The timing campaign will predeclare AB/BA block order, warmups, sample counts, timer-query limits and paired uncertainty criteria. Capture EXT_disjoint_timer_query_webgl2 results for the whole native render, and separate pass attribution only when hooks preserve the graph and sum meaningfully. Preserve disjoint, pending, overflow and invalid blocks; do not reroll a failed block to improve the result. Do not run buffer queries/readback, resource probes, CPU builds, Blender or another scene in the timing window. Record the actual background process inventory rather than inheriting historical campaign labels.

Resource accounting is separate: original, candidate increment and coexistence, actual BUFFER_SIZE where instrumented, instance capacity, programs, textures, payload bytes and cleanup to zero owned buffers. Attribute/index bytes are not physical VRAM or invocation counts. Geometry and draw overhead are included in the measured net result. The original isolated 17.476% result is context only, never the approval of this scenario.

No World timing has run for this protocol. Growth motion, completed harvest/delivery, user visual review, other crops and worker validation remain additional requirements before production or a category PR.
