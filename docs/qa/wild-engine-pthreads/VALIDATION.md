# Wild Engine pthreads: validation map

This is an index of acceptance evidence, not a declaration that every gate is closed. The chronological details and reproduction commands are in README.md. The current objective is native chunk generation; the unrelated art backlog remains paused.

| Requirement | Implemented behavior / evidence | Remaining limit |
|---|---|---|
| One authoritative shared world | spatial-thread-runtime.js supplies one shared WebAssembly.Memory to the Emscripten factory. Worker preparation consumes bounded input snapshots and moves prepared data into the main-owned authority. Native worker identity is checked. | Existing read-only far-scenery/preview samplers are separate from this authority; this is not a claim that the whole application has only one WASM instance. |
| Real off-main costly work | Native preparation includes procedural payload, static movement rasters and sector overlay data. thread-preparation.json and thread-publication.json test worker execution and equivalence. | Main-thread queries and graph publication remain main-owned intentionally. |
| No regeneration at publication | Prepared data/raster ownership is transferred after revision checks; published payload is selected directly. In-game reports separate generation, admission, publication and graphics installation. | Publication and graphics adoption have nonzero CPU cost. |
| Concurrent correctness | Six-biome/profile route differentials, wall/door/polygon changes, settlement and suppression revisions, stale rejection/retry, cancellation races, browser edits, crop rendering and full save reload. | Finite tests cannot prove every possible race; broad campaign soak testing is not replaced by these cases. |
| Cancellation and teardown | Idle/running/ready browser disposal cases; native cancellation; full-game return to menu; pool-return observation before termination. | Cancellation is cooperative between preparation stages, not unsafe interruption inside an individual raster. |
| Memory growth and reuse | 429 publication/removal cycles in Node and Chrome, six profiles, repeated and disjoint regions; 16 to 40 MiB shared capacity, no additional growth on later passes; post-growth JS/native roundtrip. | Capacity is not exact live heap/RSS or peak stack use. Packaged runtime reports 64 KiB reserved per worker stack; this is not measured peak usage. |
| Six-biome real rendering | Previous equivalent-work ABAB and active-world smoke in all six biomes; fixed512 Mangroves and fern LOD retained. | matrix-media-full-far completed all 24 runs with all far preparation settled. Means improve in every pair, but worst-frame stalls often increase; complete itinerary duration is not uniformly lower. |
| Background visual correctness | Late frozen captures of Sabana, Gran Rio and Volcanes show ground under distant trees after all far preparation ends; Sabana also checked with standalone. | Transient gaps during camera travel remain; this is not zero-pop streaming acceptance. |
| Optional follow-up optimizations | Batch eviction, shader retention, staged graphical installation, incremental shore preparation and native-grid shore sampling have independent QA controls. | They remain off by default. Native-grid does not consistently improve whole-itinerary latency with the corrected far gate. |
| Browser fallback | Real no-isolation and failed-module probes select standalone safely. | Fallback remains synchronous and retains its native CPU stalls. |
| Distribution | Earlier current-source checkpoints built itch ZIP and Windows Tauri release; WebView2 native pthread and full-game startup smoke passed. | 3f21b8353 rebuilt successfully. Fresh runtime passed six biomes in nested and delegated cross-origin iframe; Windows/WebView2 pthread and full-game smoke both exited zero with ok=true and no errors. No actual itch upload, installer bundle or non-Windows desktop execution is claimed. |

Optional experiment results must not be conflated with the default pthread path. Full-frame and background readiness, not an isolated function time, govern the remaining performance decision.
