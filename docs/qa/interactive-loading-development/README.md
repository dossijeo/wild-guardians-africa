# Interactive loading development evidence

These are diagnostic pilots, not completed acceptance or a performance claim. The branch is still under development and no PR is open.

- `first-diorama.png` and `gameplay-after-transition.png`: first actual New Game integration. The original ground atlas experiment was subsequently replaced after visual review.
- `diorama-native-day.png`, `diorama-native-night.png`, `diorama-native-input.json`: isolated native crop/shader fixture. Mouse planting added a fifth seedling; after its catch-up it matched the initial four at 55%. Clicking the occupied position did not add a sixth. The day/night toggle uses the real clock threshold. The fixture slider is a manual presentation control, explicitly distinct from production progress.
- `pilot-integrated-sabana.json`: real weighted initialization and cinematic with CPU duration wrappers. Diorama ready 1,109.8 ms; visible world 18,832.6 ms; control 22,905.7 ms. Maximum delivered interval 1,596.4 ms, primary world render 1,583.8 ms. This fails responsiveness acceptance.
- `pilot-batched-sabana.json`: same recipe with native screen/shadow draws in batches of four and a full final shadow pass. World ready 16,024.1 ms; control 20,170.9 ms. Maximum interval 515.5 ms; two draws still cost 508.1/505.4 ms. This remains above acceptance; further investigation required. These independent warm-cache pilots are not ABBA and cannot establish a loading-time gain. Transport/cache differed, notably walls.

Both integrated pilots used Sabana/Mapungubwe, seed 712, media. Four previously inventoried Node campaigns remained active (35912, 49032, 41304, 41320); root and FrontSide avoided overlapping GPU/Blender/heavy suites. These runs do not claim device-independent timing, GPU timer results or exact peak RAM/VRAM. Heap/resource snapshots are coarse observable proxies.

Native tabs were disposed and closed after each run; the context reported lost after disposal. Latest isolated visual run had no console errors/warnings. The earlier integration had existing environment shader warnings recorded in its console JSON. Lifecycle tests cover borrowed ownership, compilation cancellation, worker cancellation and camera restoration; full production lifecycle/coverage is still pending.

## Upload investigation (diagnostic, not acceptance)

- `pilot-shadow-timing-sabana.json`: world ready 16,421 ms, control 20,483.7 ms, maximum frame interval 532 ms. Large color renders still cost 473.5/523.4 ms; the longest shadow submission was 150.6 ms. Shadow batching alone cannot explain or remove those stalls.
- `pilot-texture-upload-sabana.json`: world ready 18,818 ms, control 22,888.5 ms; maximum interval 448.7 ms. Explicit uploads moved synchronous work out of color draws, but individual HTMLImage uploads still took 47–266.7 ms (1024²/2048²), plus 225.3 ms for a 4096×2048 image. KHR_parallel_shader_compile was supported. This remains above responsiveness acceptance; it is not an improvement claim.
- `image-bitmap-pixel-parity.json`: GPU readback of native biome base/normal/metallic-roughness and all six soil colors, preserving the original Texture owner, sampler, unpack and color-space settings. Eight of nine comparisons are bit-exact. The desert 1254² texture differs in 29 of 262,144 channels, maximum one 8-bit level, mean 0.000110626 levels. The predeclared acceptance tolerance is maximum ≤1 level and mean ≤0.05 levels: it permits sub-LSB resampling/rounding, never a visible orientation, premultiplication or color-conversion discrepancy. All nine pass. This measures fidelity only; no timing claim.

The optional loading image path awaits image.decode and creates a no-flip/no-premultiply/no-color-conversion ImageBitmap. Disposal closes it only through the original texture owner; cancelled late arrivals close before assignment. Compiled active samplers determine upload selection, avoiding six unused maps found in the greedy diagnostic. Model GLTF texture loading is unchanged. Pixel parity does not imply a faster upload; the next integrated timing pilot must establish whether driver work is reduced.

The cinematic now pre-renders its safe elevated reveal and final gameplay eye under the diorama before visible readiness; it remains unarmed until progress and plant maturity are verified. No simulation time or save state advances. The sky handoff interpolates the diorama FOV to the real camera FOV before the sky-only switch.

## Fifth native diagnostic

`pilot-decoded-textures-building-worker-sabana.json`: diorama interactive 1,153.9 ms; world readiness 20,624.3 ms; control 24,760.5 ms. Maximum interval 415.7 ms, 18 >50 ms and five >100 ms. Console empty; disposal reports context loss. Original 2048² uploads now submit in approximately 29–43 ms, and 4096×2048 in 54.5 ms. Cache/transport and simultaneous CPU changes prevent treating these independent pilots as an ABBA or total-time improvement. Responsiveness acceptance is still outstanding.

The native building kernel runs in a dedicated loading Worker using copied source arrays. Prepared groups, repaired normals, ash, fitted hit sites and noise return by transferable typed arrays; main rehydrates the unchanged runtime damage/picking closures. All five cultures compare exactly for geometry, seeds, UVs, holes, field queries, collapse and raycasts at six damage states. The generated module and extraction generator match; manifest hash was updated. Compatibility fallback is synchronous and documented, never described as non-blocking. Worker completion/error/cancellation terminates ownership.

The remaining 371 ms task lies in biome preparation, 315 ms in far preparation and a 273.6 ms draw accompanies the first fogged far view. Follow-up code moves native tangent calculations to a loading Worker, transfers a disposable binary copy, and budgets prototype attachment across frames. Six-biome typed-view samples retain identical tangents. World shader warmup uses the eventual linear-fog variant when a far profile exists, avoiding compilation of a temporary fog-free variant. These follow-ups await the next native pilot.

## Sixth native diagnostic and subsequent bounded preparation

`pilot-tangent-worker-final-fog-sabana.json`: diorama interactive 1,094.5 ms; world readiness 21,991.1 ms; control 26,043.8 ms. Maximum interval 332.5 ms, 23 >50 ms and eight >100 ms, over 1,332 delivered intervals. Largest world draw 65.8 ms; the earlier 273.6 ms first-fog draw no longer appears in this diagnostic. Total readiness is still slower than earlier independent pilots and cannot establish an improvement: these are not ABBA measurements. Eight existing `f_environment4` shader warnings, no errors; context disposed/lost and tab closed. The original four background campaigns remained present and no root GPU/Blender benchmark overlapped.

The remaining 340 ms task occurs during far attachment, 231 ms in biome preparation and 231 ms during initial-site preparation. Shader submission reached 63.9 ms; a 4096x2048 upload reached 55 ms. Partial GPU preloads also repeatedly invalidated global proxy shadow batches. Follow-up code keeps shadow defines enabled while reusing the existing shadow map during partial color batches, then invalidates a single complete final shadow pass. Borrowed flags and visibility restore after each batch and on cancellation. Ownership tests cover this behavior; native visual/performance validation is pending.

The initial-site search now runs the original deterministic Navigation/village search in a dedicated owned Worker. Only successful non-stale completion adopts its resulting settlement configuration and clears dependent caches. Six-biome site/configuration/terrain comparisons are exact; cancellation and errors leave the original configuration untouched. The compatibility fallback remains the earlier cooperative search; a single candidate can still block.

Far-ground optional loading requests compute water samples in the existing far Worker at the final Float32 vertex positions and transfer their buffer. The attachment consumes those values instead of recalculating them on the main thread. Six-biome masks, position/color/index arrays and genuine Node Worker transfer/detachment compare exactly. Non-loading callers retain their original path. These changes await a frozen native pilot before any timing claim.

The seventh attempted pilot was invalidated by a Vite full reload caused by editing watched source before exporting its report. It supplies no accepted timing or visual evidence. Its old document cleaned up on pagehide, and the replacement document had not initialized a renderer when the tab was closed. Future timing windows freeze source until export, disposal and tab closure.

## Real-app cancellation and next compatibility fixture

`real-app-cancellation.json` and `cancelled-new-game-menu.png`: actual menu entry prepares the diorama during the native journey. Returning from the selector removes the top-level prepared canvas. Starting New Game displays the native loading canvas; Cancel returns to the native menu with no remaining top-level world canvas and no console warnings/errors. A second preparation/start succeeds and Escape cancels back to the menu. This was functional coverage only, while root ran its CPU suite; no timing is accepted from this round. The QA tab was closed.

Chunk/actor failures raised through WorldScene.onError now abort the loading transaction and return an error to the menu, instead of leaving the visible progress stalled. Gameplay retains its prior error handling. The integration fixture adds in-flight cancellation, exact logical/camera invariants around the cinematic, reduced-motion selection and an archived dense Continue case. Its gzip input is copied locally from the previously archived 1122-crop QA save to `.cache/loading-dense-save.bin`; it is not bundled into production or committed as a new asset. This additional native compatibility coverage is not yet complete.
