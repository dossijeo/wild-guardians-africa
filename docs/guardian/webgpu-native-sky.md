# WebGPU native sky

`createWebGpuNativeSky` loads the game's two original RGBE panoramas, decodes them with the existing auxiliary Worker pipeline and evaluates their original sky formula in a single TSL background node: decoded-radiance bilinear interpolation, exposure, saturation, star layers and the same analytic `skyNight` transition. `update(camera,state)` reads the confirmed simulation state; camera changes update only uniforms. Fetch, decode and GPU resources are cancelled or released on disposal, and a failed preparation cancels the peer task and does not replace the current background. The old background remains until the panoramas are ready.

`tools/experiments/audit_webgpu_native_sky.mjs` renders day, transition and night with one fixed camera in a strict WebGPU OffscreenCanvas Worker and compares readbacks with the existing NativeSky WebGL renderer as a reference only; readback orientation is aligned. In one run, mean absolute RGB differences on a 0–255 scale were 0.003, 0.197 and 0.001 respectively (maxima 1, 4 and 7). `webgpu-native-sky/day-{reference,webgpu}.png` and `night-{reference,webgpu}.png` contain the paired images. `tests/webgpu-native-sky.test.js` checks confirmed time, pause stability, disposal and cancellation.

This is not a full-game visual or performance comparison. The isolated lab option `skyAtmosphere=clouds` is not ported; the standard approved NativeSky recipe is used. Environment reflection textures and special atmosphere effects are still separate work. Pipeline compilation and initial GPU upload occur on the graphics Worker and have not been profiled for contention. Backend/device loss is managed by the surface, and the component does not create or own the renderer.
