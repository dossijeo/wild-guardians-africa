# Experimental WebGPU picking

`qa-webgpu-picking` enables an asynchronous, on-demand Worker endpoint for confirmed animals, crop bounds and resident terrain. `wildGuardiansWebGpuPickQa(clientX,clientY)` converts client coordinates and returns the hit and confirmed state sequence; request IDs correlate out-of-order responses. `tools/experiments/audit_webgpu_confirmed_picking.mjs` exercised the endpoint in a real WebGPU raid with 16 animals. Unit tests cover animal, crop, terrain and response ordering.

Resident terrain, building and vegetation geometry now occludes targets. The client sends the latest camera and rejects responses after a newer request, camera change or below the requested minimum state sequence. Actual visible target picking still needs real-world validation; alpha-cutout leaves and GPU-deformed geometry are not represented exactly by CPU raycasts. The result is not a performance measurement.

QA update: discrete Attack, Grow and Multiply clicks are routed through the Worker when `qa-webgpu-picking` and the WebGPU game are enabled. The adapter synchronizes the camera first, keeps the gesture duration, drops responses from stale cameras or a replaced tool/world/Worker, and sends the target to the existing authority validation. If the Worker is unavailable, or an unsupported interaction is active, the existing click path is retained. Walls and strokes, general selection, terrain placement and Shield still use the original scene picker. This is a QA integration, not removal of the legacy scene; the asynchronous path needs real-input and visual-parity validation before broader adoption. In particular, selection may be discarded while the camera is moving. Its latency has not been measured.

The QA picker now also identifies visible workers and entity-bearing structure groups, applying depth, visibility and alpha-cutout checks before returning the nearest hit. Awakening may use that picker when the confirmed actors, structures and crops are resident; an incomplete visual scene, a pending terrain batch, a crate or an unsupported structure causes the interaction to fall back to the existing picker. General selection, wall strokes and placement still use the original path. Tests cover selection order, terrain and foliage occlusion, readiness, fallback and stale interaction responses. Actual clicks, visual parity, omitted resources and latency remain unverified in game; these checks do not yet justify retiring legacy actor poses.

A real-scene QA probe selected animals and plants and verified a wall occlusion with the same camera and state: a crop was hidden by the wall and became selectable when only that wall was hidden. No suitable real tree occlusion case was found. Edge reported an NVIDIA Turing adapter without exposing its exact model; this is a functional test, not a benchmark.

The QA picker now samples cutout texture alpha lazily, falling back to conservative occlusion when pixels or UVs are unavailable. Unit tests cover transparent cutouts; a bounded real-scene search did not find a suitable controlled tree case. Filtering, mipmaps and GPU-deformed geometry can differ from the raycast, so this path remains QA-only.

Auditoría ligera de entrada real: se intentó cargar `qa-worker-game`, `qa-microevents-fixture=wood`, `qa-webgpu-world` y `qa-webgpu-picking`, sin incursión ni recuperación, en Edge headless sin forzar SwiftShader. El navegador anunció WebGPU, BC y consultas de tiempo, pero no se obtuvo identidad del adaptador. Un vigilante externo cerró únicamente los procesos de esa sesión cuando su memoria residente conjunta alcanzó 3.305.807.872 bytes durante la carga inicial; no se llegó a la pantalla de juego ni a efectuar el clic. La prueba es inconclusa y no permite atribuir ese consumo a una GPU, proceso o subsistema concreto. Debe investigarse la carga antes de repetir este escenario; la validación de clic real sigue pendiente.
