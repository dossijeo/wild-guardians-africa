# Worker baked walking — experimental integration

All four worker previews' `Walk_Skip` clips are reproducibly baked from the production CPU pose implementation with `node tools/guardian/build-worker-gpu-walk.mjs`; `--check` regenerates and compares both files per profile, and `--profile=youngMale` selects one profile. The source preview and baked binary are SHA-256 checked. Each rig shares 28 bone matrices across its three or four skinned meshes; all rigid attachments are hidden in every sampled walking pose.

The explicitly selected WebGPU Worker game profile enables `presentationCapabilities.bakedWorkerWalking`, independently of the animal `bakedWalking` capability. This installs walking for all four supported worker profiles; animal animation keeps its independent path. The default legacy backend is unchanged. The original shared `bakedWalking` capability still enables both banks for comparison. The roster asynchronously acquires one shared GPU texture per profile, admits the alternative pipeline before publication, and continues to use the original rig when loading, compilation or rig validation fails. Disappearance and shutdown cancel pending loads; GPU texture disposal waits for outstanding compilation. Authoritative motion and gameplay are unchanged.

Only confirmed `walking`, `arriving` and `returning` `Walk_Skip` states use this path. Carrying, tools, action, running, recovery, fall and recovery-exit blending keep the original CPU path. Facial morph arrays remain shared with the original mesh and expression controller; picking reconstructs the current baked pose. A return to CPU explicitly resamples the original rig. Data-driven GPU interpolation uses confirmed simulation time and can pause with it.

Automated tests use all four actual preview rigs and baked files, a simulated renderer and GPU-admission contract: they check shared morph arrays, frozen CPU bones during baked walking, transitions back to CPU for carrying, running, gate waiting, falls, incapacitation and recovery exit, sampled vertex parity following a carrying-to-walking transition, shared bank lifetime, cancellation and checksums. They are not a WebGPU rendering or visual parity test. Pending: compare animation, blink, tools and transitions in a real playable WebGPU scene, including shadows and progressive texture updates, before adopting this path in the default backend. No FPS or physical GPU pipeline reuse claim is made.
