# Worker baked walking — experimental integration

The `youngMale` preview's `Walk_Skip` is reproducibly baked from the same production CPU pose implementation with `node tools/guardian/build-worker-gpu-walk.mjs`; `--check` regenerates and compares both files. The source preview and baked binary are SHA-256 checked. Its four skinned meshes share the same 28 bone matrices; all 24 rigid tool meshes are hidden in every sampled walking pose. Other worker profiles are intentionally unsupported and keep their live rig.

The explicitly selected WebGPU Worker game profile enables `presentationCapabilities.bakedWorkerWalking`, independently of the animal `bakedWalking` capability. This installs walking for supported `youngMale` workers; all other profiles and animal animation keep their original paths. The default legacy backend is unchanged. The original shared `bakedWalking` capability still enables both banks for comparison. The roster asynchronously acquires one shared GPU texture for the profile, admits the alternative pipeline before publication, and continues to use the original rig when loading, compilation or rig validation fails. Disappearance and shutdown cancel pending loads; GPU texture disposal waits for outstanding compilation. Authoritative motion and gameplay are unchanged.

Only confirmed `walking`, `arriving` and `returning` `Walk_Skip` states use this path. Carrying, tools, action, running, recovery, fall and recovery-exit blending keep the original CPU path. Facial morph arrays remain shared with the original mesh and expression controller; picking reconstructs the current baked pose. A return to CPU explicitly resamples the original rig. Data-driven GPU interpolation uses confirmed simulation time and can pause with it.

Automated tests use the actual preview rig and baked files, a simulated renderer and GPU-admission contract: they check shared morph arrays, frozen CPU bones during baked walking, transitions back to CPU, sampled vertex parity following a carrying-to-walking transition, shared bank lifetime, cancellation and checksums. They are not a WebGPU rendering or visual parity test. Pending: compare animation, blink, tools and transitions in a real playable WebGPU scene, including shadows and progressive texture updates, before adopting this path in the default backend; extend authored data to other profiles only after equivalent checks. No FPS or physical GPU pipeline reuse claim is made.
