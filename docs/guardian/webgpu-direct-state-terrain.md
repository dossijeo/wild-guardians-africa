# Direct confirmed presentation stream

The hosted simulation can optionally send ordered confirmed publications directly to a presentation Worker through a dedicated MessagePort. It uses the existing bounded publication queue: one in-flight publication, coalescing compatible quiet ticks, retaining event and invalidation boundaries. An acknowledgement advances the independent presentation queue; a malformed acknowledgement or more than 256 pending entries closes that visual stream without stopping the authoritative simulation. This is not recovery from visual stream failure: restarting and resynchronizing a presentation Worker remains necessary.

The receiver reconciles authoritative state and events before releasing terrain for that sequence. This stream does not itself move actors, render physics poses, or provide the complete production scene. It is optional and does not replace the existing game renderer.

`tools/experiments/audit_webgpu_confirmed_terrain.mjs` runs the real hosted simulation and a WebGPU-only OffscreenCanvas Worker with separate direct state and terrain channels. The recorded run in `webgpu-direct-state-terrain.json` used the mangrove island network, received both requested native terrain chunks at confirmed sequence 8 and drew them. It is a functional smoke test, not a performance comparison or a gameplay validation. Its run did not deliver gameplay events; ordered event reconciliation and gap rejection are covered by `tests/confirmed-presentation-stream.test.js`, and queue coalescing and barriers by `tests/host-publication-queue.test.js`.

Remaining integration: production WebGPU world and materials, actor and physics presentation, complete event handling, session restart/resynchronization, gameplay, deterministic campaign comparisons, and actual latency/frame-time measurements. The WebGPU character/terrain Workers do not yet constitute a migrated playable raid.

A reusable experimental world surface now owns the WebGPU renderer, camera, confirmed state receiver and native terrain residency inside a Worker. `src/rendering/webgpu-world-worker.js` runs it continuously and accepts camera and resize messages, including updates received during initialization. `tools/experiments/audit_webgpu_world_worker.mjs` exercises this worker with the real hosted simulation and WebGPU-only contexts; it checks startup and a submitted first frame, not completed GPU work, visual quality or production gameplay. The existing confirmed-terrain and delayed-chunk audits exercise the reusable surface and validate visible terrain separately. This worker is not yet connected to the game canvas; the existing renderer and WebGL compatibility path remain intact. The surface intentionally uses provisional vertex colors and does not yet display characters or world props.

The opt-in `experimentalActorId` path now loads the original species GLB in the WebGPU presentation Worker, selects its native animation from the confirmed simulation state, and places one real raid animal on the published native terrain. Its pose is sampled on confirmed publications, not autonomously in GPU; the worker still evaluates a Three.js mixer. Terrain publication reapplies the presentation placement when a new chunk arrives. The browser audit uses animal-7744 (warthog) from the mangrove raid fixture. `webgpu-worker-confirmed-warthog.png` shows the current result and exposes substantial presentation differences: approximate ground support, provisional lighting/material handling, absent world objects and no production combat/ragdoll treatment. It is not a visual equivalence result, playable integration, or performance measurement. The model is requested after surface startup without awaiting its load. The audit intentionally holds the GLB response until after the first submitted frame, then confirms the requested actor loaded. This verifies ordering only: an actor placeholder, nonblocking pipeline preparation, first-use frame times, quality parity and cancellation of the network request remain to be addressed. A pending load finishing after disposal releases its model resources.
