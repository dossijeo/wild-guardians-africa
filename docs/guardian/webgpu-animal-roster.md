# Confirmed animal roster in the WebGPU Worker

The experimental WebGPU world can consume all active animals from each confirmed state publication (`experimentalAllActors`). It creates or removes presentation instances as authoritative animals appear or leave and discards a late load if its actor was removed. A shared bank loads each species once, shares geometry, materials and textures, and clones independent skeletons for each animal. Its references include pending acquisitions; after the last actor releases a species, the shared resources are disposed. A cancelled surface closes outstanding loads. The buffalo may use the existing progressive vertex-color/BC7 or WebP package; other species currently load original textured GLBs. This feature does not advance simulation.

`tests/webgpu-animal-roster.test.js` covers sharing, independent instances, removal, late completion and disposal. `tools/experiments/audit_webgpu_real_roster.mjs` connects a real hosted simulation and a strict WebGPU OffscreenCanvas Worker to the mangrove island-network fixture. One observed run created 16 animals across warthog, hyena and buffalo, with one original GLB request per non-progressive species. It checks load and roster counts, not visual parity, collisions, animation quality, frame time, GPU memory or game completion.

Limitations: placement, terrain support and lighting remain provisional; animations are sampled by a CPU-side mixer on confirmed state updates. Physics poses, ragdolls, impacts, interpolated GPU trajectories, shadows and player feedback are not yet integrated; workers are absent. Texture transitions are shared per species, not individually controlled. A generation of assets that arrives after shutdown is disposed, but device-loss recovery requires recreation of the full surface. The old game presentation is still active underneath the development WebGPU canvas, so this is not an optimization or a production-ready replacement.
