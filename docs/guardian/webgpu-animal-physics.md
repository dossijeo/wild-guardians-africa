# Confirmed Rapier animal poses in the WebGPU Worker

The Worker reconciles complete authoritative publications, validates all physical poses against the incoming snapshot and any loaded visual rig before mutating presentation, and installs accepted poses before notifying presentation events and releasing terrain. The actor roster retains the latest accepted physical pose while its model is loading. Each rig applies the root, model and bone transforms from Rapier; when the authority releases the actor, the original model/bone transforms are restored and its ordinary confirmed-state animation resumes. The presentation does not create a solver or alter simulation.

The authoritative ragdoll binding may synthesize `LeftToeBase` and `RightToeBase` as collider endpoints. These are not skin joints. The WebGPU actor ignores only those named auxiliary endpoints when they do not exist in its visual rig; all other bone names, order and transforms must match exactly. A browser comparison of all five original animal rigs and the compressed buffalo preview found 21/23 hyena, 78/80 lion, 21/23 warthog, 61/63 buffalo and 76/78 rhino visual/physical bones, with the remaining bones in identical order.

`tools/experiments/audit_live_webgpu_physics.mjs` started the real game in development mode with an existing savanna raid, selected Attack via the HUD and invoked the same pick handler using the QA direct target. The Worker applied a physical pose to the animal, observed falling, rolling and recovering, and resumed normal animation after its pose was released. Unit tests cover validation before state mutation, event/pose order, late-loading actors, malformed rigs and restoration. This one controlled run does not establish visual parity, simultaneous impacts, GPU animation, save/restore or performance improvement.
