# WebGPU wall impact presentation

The WebGPU world now consumes `materialVfxPlans`, the same confirmed `AnimalLogicalHit` plans used by the existing wall impact presentation. Wood, adobe and stone impacts reuse the native particle composition, shared VFX atlas, ground projection and simulation clock. Shielded hits do not create a wall impact effect. The existing WebGL implementation is unchanged and there are no simulation or collision changes.

Run `node --test tests/webgpu-agriculture-vfx.test.js` with Node 20 to cover confirmed wall hits for brambles, adobe and stone, as well as expiry. `tools/experiments/audit_webgpu_agriculture_vfx.mjs` tests the WebGPU OffscreenCanvas path with Playwright through `NODE_PATH`; one run drew six adobe-hit sprites without uncaptured GPU errors. `tools/experiments/audit_live_webgpu_first_wall_hit.mjs` starts the real Worker raid from a prepared state with an animal attacking an intact wall. One run observed confirmed `StructureHit` and `AnimalLogicalHit` events and six WebGPU wall sprites. This is a prepared scenario, not proof of natural navigation. The unmodified raid in `tools/experiments/audit_live_webgpu_raid_wall.mjs` ended after crop attacks without a detected wall hit. Rigid splinters/chunks, local lights and soft depth are not yet drawn in WebGPU, and visual parity is not established.
