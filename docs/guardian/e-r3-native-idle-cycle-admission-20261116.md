# Native Idle cycle: existing prepared transaction

Continuation of `e-r3-native-idle-cycle-control-20261116.md`, on the existing
native owner, common resource-admission factory and direct control publication.
This component does not close A6, A, B or C.

An initialized stationary body can now propose its finite rest/watch cycle
through `prepareNativeIdleCycleProposal(actorId)` and
`startNativeIdleCycleAfterGpuQuiescence(...)`. The frontend checks the actual
Game worker, physical ancestry, original pose/profile, contract and current farm
anchor. It uses the existing locomotion calibration and native private stream;
JavaScript neither advances the policy nor chooses its stochastic successor.
An actual subsequent REST request can use the same operation once its semantic
state is projected. A pending stroll is refused and receives no movement grant.

The existing transaction stages once, prepares a retained resource handle,
drains its registered consumer, revalidates the current native proposal, checks
compatibility, commits synchronously and publishes its exact association before
release. A later native clock can translate the prepared epoch without another
preparation. Changed Game semantics, source, anchor, session or intent prevent
acquisition. Cancellation releases the draft; a failure after physical commit
closes control and reports `committed-control-failed`, without claiming rollback.

The shared profile now names the typed family21 template, binding and release
array. The existing preparation client, connection and receiver carry that
template, including invalidate/refresh. The control publication validates the
matching receipt and actual committed cycle attestation. It rejects missing,
duplicate, foreign or mixed-family attestations before sending a release. No
additional registry, queue, clock, scene owner or dependency was introduced.

Before implementation, the actual Dawn `KnownObjectsBase::FillReservationImpl`
was read at revision
[`922930e3193753e58591f14a96ab116e5d630964`](https://github.com/google/dawn/blob/922930e3193753e58591f14a96ab116e5d630964/src/dawn/wire/server/ObjectStorage.h).
It requires the reserved state and matching generation before completing an
allocation. Wild Guardians applies that boundary pattern to its existing native
session, ticket, source sequence and immutable program. These are different
identity schemes; Dawn is a reference, not a new runtime dependency. The actual
shared factory and family20 implementation were inspected and extended rather
than replaced.

Validation details and exact totals are in
[`performance/native-idle-cycle-admission-validation-20261116.json`](performance/native-idle-cycle-admission-validation-20261116.json).
The directed tests use real WASM, publication, resource client/receiver and two
MessageChannels. Their retained-resource consumer and drain are simulated;
they do not compile or draw a family21 GPU graph. They exercise advancing peer
motion, native revalidation, cancellation, semantic mutation, source removal,
bad receipts, subsequent REST, pending stroll rejection, zero-duration watch,
typed refresh and post-commit release failure. The successor REST test supplies
the actual native semantic state explicitly; it is not an ordinary Game producer.
