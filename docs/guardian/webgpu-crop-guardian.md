# WebGPU Grow and Multiply guardian feedback

The existing locally validated crop command now begins the guardian on the WebGPU render Worker with its command ID, original target and placement. The confirmed `SpellActivated` event reconciles the gesture and existing agricultural VFX; rejection clears the matching provisional. The guardian uses the existing model, clips, aura and spirit material. Grow renders two hand-fed rays and Multiply renders eight branching rays after confirmation, using one instanced draw. No crop effect or benefits are invented before the simulation confirms the action. The previous WebGL presentation remains available.

`node --test tests/webgpu-guardian-attack.test.js tests/webgpu-world-client.test.js` checks command ordering, rejection and the absence of unconfirmed rays. `tools/experiments/audit_webgpu_guardian_crop.mjs` renders the real model in an OffscreenCanvas WebGPU Worker; a run observed eight Multiply rays and 14,436 visible pixels. With `QA_WEBGPU_WORLD=1`, `tools/experiments/audit_live_webgpu_crop_guardian.mjs` drives the existing peaceful real-game fixture; the Grow and Multiply runs observed the same command IDs in WebGPU, respectively two and eight confirmed rays and one confirmed agricultural effect. The script also tests a second rejected command. Set `QA_CROP_SPELL=multiply` for Multiply. Node 20, the Vite server and Playwright through `NODE_PATH` are required.

These are integration checks, not a visual A/B or a performance measurement. Hand/eye aiming, wind deformation and the original lighting details are still incomplete. The original audio and other legacy visual paths have not been migrated by this change.

A stricter real-fixture run for both Grow and Multiply verified the render Worker receives the rejected second command, clears its provisional state and beams, and emits no duplicate activation. This run used headless SwiftShader and is a functional check, not a GPU performance or visual parity measurement.
