# WebGPU world integration in the game (development gate)

`?qa-worker-game&qa-webgpu-world` attaches the presentation Worker to the live game's hosted simulation via direct confirmed-state and native terrain channels. The Worker owns its OffscreenCanvas and explicitly rejects a non-WebGPU backend. Camera poses are sent immediately with at most one update in flight; newer pending poses replace older ones. The old world remains active underneath for gameplay, picking and visual reference: this is an intentionally incomplete diagnostic integration, not the desired final architecture and not a performance path. The WebGPU canvas currently shows native terrain, provisional native water and, when the initial raid contains an animal, one experimental actor. All other world content, materials, lighting, effects, animation/physics presentation and visual parity remain missing.

`tools/experiments/audit_live_webgpu_world.mjs` opens the actual game and checks the real hosted simulation, a confirmed WebGPU state sequence, resident terrain and a menu pause. `QA_RAID=1` uses the existing mangrove raid fixture with the same island-network conversion as the simulation tests and marks it with the current Wild Engine world version for this diagnostic; it is not a saved-game compatibility test. It selects the buffalo and the checked-in progressive package and waits for its texture transition. The fixture is not an end-to-end campaign or a visual acceptance test. No frame-time improvement can be inferred, since the legacy renderer is still active.

The buffalo package uses BC7 when supported and WebP otherwise. An isolated Worker test observed 4 to 4 pipelines for BC7 and 4 to 6 for WebP; a failed texture fetch retains the preview. Other species currently load the original full model. The animation mixer and placement are still CPU Worker work. Confirmed GPU motion is available as a separate component, but the game cannot safely use it until authority publishes usable timed trajectories with a simulation clock, ordered invalidations and physical-pose handling. WebGL remains available as a compatibility path, and production has not switched to WebGPU.

Verified integration smoke: the normal game started with WebGPU, 15 resident native chunks and a paused hosted simulation. A second run used the explicitly converted mangrove raid fixture, received confirmed sequence 25 and 28 native chunks, displayed the selected buffalo with its textures applied, and paused the simulation. These are individual headless runs and do not establish visual parity, a complete raid, stable frame times, or production readiness. The provisional canvas replaces the visible world only in this development mode, while the old world still runs underneath.

Follow-up integrated raid smoke: with the explicitly converted mangrove fixture, `QA_RAID=1 QA_ALL=1 QA_PROPS=1 QA_MOTION=1 QA_DEVICE_LOSS=1 node tools/experiments/audit_live_webgpu_world.mjs` observed WebGPU, five confirmed resident chunks, 43 instanced vegetation batches, all 16 animals ready, one tracked confirmed-motion actor and the buffalo texture transition. The audit destroys the WebGPU device, confirms the experimental canvas disappears and the authoritative hosted simulation remains active, then verifies pause. This verifies a controlled failure path in development mode; it is not a visual parity, full-raid, hardware performance or production fallback certification.

The animal bank shares source geometry, materials and textures within each species and uses independent skeletons. The vegetation uses confirmed native instances and existing near tree assets in every distance; its lighting, LOD, water and surfaces are provisional, with no buildings, rocks, crops or visual effects yet. Physical animal poses, ragdolls, workers and GPU animation remain unimplemented. The motion feed validates ordered traces and revokes them on invalidation, pause or physical ownership; it does not drive GPU movement. The live game still evaluates and draws the legacy scene underneath the development canvas. This duplication is temporary and prevents interpreting any of these runs as evidence of a performance improvement.
