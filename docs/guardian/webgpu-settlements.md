# Experimental WebGPU settlements

`createWebGpuSettlements` consumes the confirmed presentation state and resident native terrain. It loads the existing authored culture-specific village geometry/atlas, original center GLB and Bastion wall geometry; it creates, updates and removes entries without altering simulation state. A missing terrain chunk hides the affected structure until the corresponding confirmed native terrain arrives. Village unit transforms and wall morph/gate geometry reuse the existing game rules. Assets are shared within each loaded culture/material; walls still maintain independent presentation geometry.

For the initial Mapungubwe center, the pilot package `/content/structure-preview/center-mapungubwe/package.json` uses the existing worker-owned progressive material system and BC7 when supported, otherwise WebP. The source-equivalent geometry and vertex colors are available before the three source textures. The center's fine patterns are temporarily less detailed, then return with the full textures and normal map. For zarzas walls, `tools/experiments/bake_wall_vertex_preview.mjs` reproducibly derives linear RGB vertex colors from the existing wall atlas and UVs. The sidecar is checked against its binary hash and each source UV hash before use. A stable TSL material mixes those colors into the original atlas once it is available; the geometry remains unchanged. Other cultures and wall types currently load their original full textures.

`tools/experiments/audit_webgpu_settlements.mjs` uses a real WebGPU OffscreenCanvas Worker, a mangrove raid fixture, existing assets and a temporary flat reference ground. The audit intentionally holds the center's three texture files and the wall atlas: a village with ten original units, one center and three walls renders from provisional colors; after the gate is released, both texture transitions complete and removed walls disappear. In one observed BC7 run, the test recorded five WebGPU pipelines before and after. This is not a frame-time benchmark, full gameplay, or proof of visual parity. The textures remain full resolution after loading; the provisional colors cannot reproduce fine pattern detail.

Limitations: center damage/destruction still uses an intact model: the original GLSL destruction pipeline, dust, fire and ash have not been migrated. Vertex-color packages cover Mapungubwe and zarzas only; villages and other structures use their full textures. The floor is raycast from resident terrain; if no chunk is resident, that structure remains hidden until terrain arrives. Lighting, shadows, visual equivalence, all cultures, all wall types, streaming and interactions require full game validation. The normal production renderer is unchanged. The component is intended for integration into the existing experimental WebGPU game path, not as a complete replacement for the game renderer.

Production packaging validation: the color sidecar identifies its source UV data by SHA-256, without embedding the original buffer URL, so the wall-buffer packager can replace those source files with its shared bank. The build completed and all four UV ranges and the wall texture identity were checked against the packaged outputs. `tests/wall-buffer-bank.test.js` guards this contract. This validates packaging, not WebGPU runtime parity in a shipped build.
