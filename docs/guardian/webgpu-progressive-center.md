# Progressive Mapungubwe center in WebGPU

The package at `public/content/structure-preview/center-mapungubwe/` is generated by `tools/experiments/build_center_preview_package.mjs` from the original center GLB in `public/content/destruction.json`. Geometry and UVs are unchanged. The base color is sampled from the original texture at each vertex and stored in the preview GLB; source hash and all package payloads are checked by the existing preview stream. Full original textures are loaded afterwards using native BC7 KTX2 when supported or WebP otherwise. The same existing `openProgressiveWebGpuCharacter` interface works for the unskinned center using `species: 'mapungubweCenter'`; the name is a package ID, not a simulated species. `start()` begins texture loading, `tick(now)` blends and `dispose()` releases resources.

A strict WebGPU Worker test, `tools/experiments/audit_webgpu_progressive_center.mjs`, held the 3 texture responses until after the preview had rendered. The mesh, geometry and material identities remained unchanged. In one BC7 run the count stayed 2 to 2 pipelines; forcing WebP produced 2 to 4. The paired captures `webgpu-center-vertex-preview.png` and `webgpu-center-full-textures.png` show that the provisional center loses fine patterns and surface details, which return with the full textures. These are functional single-run checks, not gameplay visual parity or proof of improved frame times. The BC7 package is ~4.2 MB and WebP ~0.42 MB, plus a ~1.27 MB geometry preview. The offline builder expects the pre-existing local BC7 conversion report and source files; it does not modify original assets.
