# Experimental WebGPU guardian Attack

The development WebGPU world accepts the same locally eligible `castAttack` intent that the existing UI sends to the simulation Worker. A matching provisional guardian is keyed by command ID; a rejected result removes only its own provisional presentation. Confirmed `SpellActivated` events reconcile that ID, cannot replay it if delivery arrives before the provisional message, and cannot replace a newer chained provisional gesture with a late older confirmation. Damage, hit results, eligibility and physics remain exclusively authoritative. A down or recovering target is checked both by the existing UI and the presentation Worker. Confirmed coordinate changes are blended over simulation time.

The component loads the existing guardian GLB on demand, reuses its clips, `GuardianPose`, facial blink/expression and `GuardianVortexWebGPU`, and renders a beam, impact ring and core using the original attack timing. A small provisional core appears before the model completes loading. The WebGPU TSL material implements the original height-based reveal, glowing edge, procedural dissolve and day/night lighting with shared uniforms. The aura now uses the original `repel` sprite simulation, density and placement through the existing WebGPU VFX atlas and shader. It follows the provisional command ID, transfers continuously to confirmation and disappears on rejection or expiry. The shared WebGPU VFX path does not yet draw the native ribbons, rigid particles or local lights; soft depth is also absent, and visual parity has not been established. Normal-map lighting and fog, hand aiming/IK, narration lip-sync and provisional animal ragdoll also remain unverified or unported. Skeleton animation remains CPU-evaluated in the render Worker. The existing legacy scene continues running underneath the development canvas.

Run `node --test tests/webgpu-guardian-attack.test.js tests/webgpu-agriculture-vfx.test.js` using Node 20, then run `tools/experiments/audit_webgpu_guardian_attack.mjs` and `tools/experiments/audit_webgpu_agriculture_vfx.mjs` against the local Vite server with Playwright available through `NODE_PATH`. The component tests passed; the real-model OffscreenCanvas audit reported backend WebGPU and a visible confirmed model. The sprite audit observed 16 aura sprites, rendered and removed the effect. These checks verify execution, not visual parity, GPU performance or loading latency. A matched WebGL/WebGPU visual comparison remains necessary.

`tests/webgpu-guardian-attack.test.js`, `tests/webgpu-world-client.test.js` and `tests/spell-placement.test.js` cover command ordering, rejected provisionals, eligibility, duplicate suppression, chained casts and unchanged simulation state. `tools/experiments/audit_webgpu_guardian_attack.mjs` uses an OffscreenCanvas WebGPU Worker and the real model; it observed provisional beam/core before the model arrived and 14,196 non-background pixels after confirmation. `tools/experiments/audit_live_webgpu_guardian_attack.mjs` opens the actual development raid, delays the authoritative Attack by five seconds and uses the existing QA pick path to check provisional render submissions, confirmation and an attempted repeat against the down target. One run observed the provisional and one confirmation; it is not a visual A/B, pipeline/frametime benchmark or proof of production completeness.

The stricter real-game run delayed the first authoritative Attack by five seconds and observed one provisional render submission with the core visible before confirmation, followed by exactly one confirmed command and the guardian model loaded. It waited until simulation time had advanced at least 1.74 seconds since the gesture began while the same animal was still down; a second attempted Attack then produced neither another provisional gesture nor another hit. The rejected-command rollback and reversed delivery cases are covered by component tests; an authoritative rejection during a real UI session is not yet demonstrated. The provisional animal ragdoll remains on the legacy path, and this experiment does not measure main-thread responsiveness or GPU frame time.

A subsequent normal Vite real-raid run observed the provisional aura with 15 sprites, a single confirmed attack, and suppression of a second attack on the down target. It does not establish pixel parity or frame-time improvements.
