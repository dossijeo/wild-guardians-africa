# Progressive textures for all center cultures and wall materials

The experimental WebGPU settlements path now uses its existing vertex-color preview and delayed original textures for the five center cultures (Mapungubwe, Suajili, Etiope, Saheliana and Musgum) and all five wall materials (zarzas, empalizada, adobe, piedra and reforzado). Center previews use BC7 KTX2 on devices with BC support and the existing WebP fallback. Wall sidecars use baked linear RGB colors and retain the original atlas after loading. Geometry is not replaced during hydration. The input source and UV hash checks remain active.

`tools/experiments/build_center_preview_package.mjs <new-output-directory> [culture]` generates a package; the existing BC7 sidecar report and encodings in `.cache/ktx2-native/glb` are required and are not checked into the repository. `tools/experiments/bake_wall_vertex_preview.mjs [material]` generates the wall sidecar. The packaged assets are checked in so gameplay does not depend on the offline conversion environment.

The four added center cultures were exercised individually in the strict WebGPU Worker via `QA_CULTURE=<culture> node tools/experiments/audit_webgpu_progressive_center.mjs`: their BC7 runs retained two pipelines before and after texture hydration. The four added wall materials were exercised via `QA_WALL_MATERIAL=<material> node tools/experiments/audit_webgpu_settlements.mjs`, each rendering provisional and fully textured walls and removing them; five pipelines were observed before and after in these controlled scenes. `tests/wall-buffer-bank.test.js` validates every wall sidecar against the packaged UV bytes. These are functional one-off tests, not frametime benchmarks or proof of visual parity. The provisional appearance lacks fine details; forcing the WebP fallback for each of the four added centers also produced an increase from two to four pipelines; appearances, errors, device loss and performance require validation across real games and hardware.

This is connected to the existing experimental WebGPU game surface only. The main production renderer has not migrated, and unrelated structures, damage/destruction, interaction feedback, animation, effects and full-game visual parity remain separate work.
