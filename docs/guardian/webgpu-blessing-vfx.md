# WebGPU blessing presentation

`createWebGpuBlessingVfx` consumes confirmed blessed plants and intact walls. It mirrors the existing delayed awakening reveal for a new `BlessingApplied` event and displays already-saved blessings immediately. Simulation time drives the procedural GPU spark motion, so pauses and accelerated time follow the authoritative clock. Terrain residency controls visibility; removal of the blessing removes its source. The shader follows the existing procedural spark and soft aura formula without an atlas. The original WebGL presentation remains unchanged.

This covers persistent blessing sparks only. It does not yet render the provisional awakening, guardian blessing ritual, impact pulse, damage fade, original crop-dependent height, or the full original composition. Default source height is one world unit until a crop height callback is supplied. No visual parity or gameplay-completeness claim is made.

Run `node --test tests/webgpu-blessing-vfx.test.js` with Node 20, and `tools/experiments/audit_webgpu_blessing_vfx.mjs` against the local Vite server with Playwright available through `NODE_PATH`. One OffscreenCanvas run reported WebGPU, 4,196 non-background pixels, and removal after the confirmed blessing disappeared. `tools/experiments/audit_live_webgpu_blessing.mjs` uses the real Worker awakening fixture and waits for the exact confirmed target in the WebGPU source list. One headless run confirmed plant-3 after the ritual delay and observed 19 particles at simulation time 3.75 s, with no runtime fault. This checks integration, not visual parity.
