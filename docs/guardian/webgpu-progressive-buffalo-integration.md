# Progressive WebGPU character integration

`createWebGpuConfirmedAnimal` accepts an optional package URL and renderer. A Worker loads the existing hashed preview/metadata package first, then requests only the supported texture variant. The preview uses the final skinned geometry and a stable node material; the material crossfades its base color and normal strength after decoded textures have been initialized in the Worker and queued GPU work has completed. The same mesh and material objects remain in place. The API exposes `tick(now)` for the presentation Worker, `onTextured`, `onTextureError` and `dispose`. A texture failure keeps the provisional appearance. The package uses native BC7 KTX2 where `texture-compression-bc` exists and WebP otherwise; it does not require a runtime Basis transcoder. This path currently creates materials and assets per actor; it is not yet a shared rig or GPU skeletal animation system.

The existing offline builder `tools/experiments/build_character_preview_package.mjs` generates the pilot package. The checked-in buffalo package includes WebP and BC7 alternatives, and its source checksums are validated on use. It consumes approximately 18.8 MB on disk; only one variant is downloaded. The package currently supports a single species, and the route remains experimental.

`tools/experiments/audit_webgpu_progressive_real_character.mjs` uses a buffalo from an existing mangrove raid state, a real WebGPU Worker and the checked-in package. In the observed BC7 run the rendered preview had 4 pipelines; after deferred texture loading and crossfade it had 4, with the frame count increasing from 26 to 50 while the transition proceeded. With BC support disabled in the test, WebP loading and transition also worked, but the pipeline count increased from 4 to 6. These are individual functional checks, not a repeated benchmark and not proof of no long frames or no driver stalls. Simulating HTTP 503 preserved the preview and the rendering loop. `tests/character-preview-package.test.js`, `tests/character-preview-stream.test.js`, and `tests/webgpu-confirmed-animal.test.js` passed (9 tests).

Limitations: lighting and grounding differ visibly from the full game; no general gameplay, shadows, ragdoll/physical poses or production visual parity is established. The animation mixer is still evaluated in the Worker on confirmed updates, not on the GPU; trajectory support is separate. The test scene does not prove performance or pipeline stability for other models or graphics hardware. The WebP pipeline increase needs investigation during integrated optimization. The current fallback uses the full original model when no package is configured, not vertex colors. Cancellation covers pending requests and resource disposal but needs extended session and device-loss validation.
