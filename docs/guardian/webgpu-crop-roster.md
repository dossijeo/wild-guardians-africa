# WebGPU confirmed crops (experimental)

`createWebGpuCropRoster` consumes reconciled crop state in the presentation Worker, loads the existing 40 original crop meshes when the first living crop is confirmed, groups living plants by authored species/stage, and shares each mesh/material through WebGPU instancing. It uses the existing growth timings and approximate height/radius interpolation, with a TSL port of the basic growth and wind deformation. It samples resident native terrain and hides a crop until its chunk is available. It does not own crop simulation or logic. Call `sync()` after confirmed state changes, `terrainChanged()` when resident terrain changes, and `dispose()` on shutdown.

`tests/webgpu-crop-roster.test.js` checks species, germination/maturity endpoints and deferred asset loading. `tools/experiments/audit_webgpu_crop_roster.mjs` loads one real millet plant from the mangrove raid fixture in an OffscreenCanvas Worker, checks real WebGPU drawing, changes its stage by changing the input snapshot, and confirms it disappears when marked inactive. It is a smoke test, not a gameplay or performance benchmark.

Limitations: the exact V4 two-second topology bridge is not ported; this experimental view switches original meshes at the transition midpoint. Blessings, damage, selections, original AfricanToon and exact visual parity are not implemented. Wind time changes only on confirmed publications, not an autonomous simulation clock. Height is approximated using the center terrain sample. No additional gameplay authority is created. Do not enable it as a production replacement before these limitations are resolved and validation passes.
