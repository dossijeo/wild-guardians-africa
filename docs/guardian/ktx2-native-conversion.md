# Native KTX2 conversion in progress

The user requested textures stored on disk in a GPU-ready KTX2 form. Three r180's installed `KTX2Loader` supports raw GPU block formats despite older documentation describing Basis-only support. This experiment encodes source images offline to UASTC and transcodes once during authoring to un-supercompressed BC7 KTX2. At runtime on a BPTC-capable device the file contains the final blocks: no Basis JS or WASM is fetched and no runtime Basis transcode is needed. BC7 is not universal: the QA path checks `EXT_texture_compression_bptc` and falls back to the original image if unavailable. Other GPU-native variants and complete fallback packaging remain to be designed and validated.

The native pilot `public/content/ktx2-native/pilot/tree01-color-bc7.ktx2` is generated from the 1024² high-resolution savanna tree texture using UASTC quality 2. It is 1,398,560 bytes versus 705,474 bytes for the original WebP; the larger download is the tradeoff for storing the final GPU blocks directly. In an isolated GTX 1660/Edge test, native parsing took 0.79–2.10 ms and `initTexture` submission 0.26–0.36 ms; the control WebP decode took 23.5–32.2 ms and submission 2.6–6.1 ms. No Basis transcoder request was observed. The native KTX and its UASTC/Basis intermediate produced byte-identical PNG readbacks in this isolated scene. Results are a short, instrumented example, not a full-game or network benchmark. Raw data: `ktx2-atlas/tree01-native-bc7-isolated.json`.

An opt-in Worker raid loaded this native BC7 into the tree's existing high-resolution UV channel and confirmed two direct QA attacks; no Basis transcoder request was observed. This verifies functional loading on one device, not visual quality across transitions or a global reduction in stalls. A separate native BC7 savanna normal map was also loaded in the raid without a Basis request; its values and lighting require wider comparison. A 1024² GLB alpha map from the lion, rendered at 256², retained 3,187 transparent and 62,040 opaque pixels; 15 of 65,536 pixels changed sides of a diagnostic alpha threshold of 0.35. This is not a silhouette or perceptual-equivalence test. Results: `ktx2-atlas/savanna-normal-native-bc7-isolated.json` and `ktx2-atlas/glb-native-alpha.json`.

The inventory `ktx2-atlas/texture-inventory.json` covers 538 external PNG/JPEG/WebP files and 312 image declarations across 132 GLBs, including sources, runtime aliases, UI and unused resources. It does not mean all are used in play. Of the external images, 169 have dimensions not directly aligned to 4×4 BC7 blocks and 192 have an alpha channel. Core GLB roles and `EXT_texture_webp` sources are recorded; extension-only or unreferenced images must not be assigned color semantics by guesswork. The 4K image first reported in this work was embedded in the original rhinoceros model; its selected web model has 2K textures. Its source alias is therefore excluded from the runtime GLB batch instead of needlessly reconverting it.

The reproducible first batches are `ktx2-atlas/biome-conversion-plan.json` (68 classified biome/near-tree role entries) and `ktx2-atlas/glb-conversion-plan.json` (132 deduplicated classified runtime GLB image/role entries; 46 source aliases excluded and three unresolved image declarations). These plans do not cover terrain, all standalone shaders, all UI or procedural textures. They are not the completed conversion of the game. Files already converted and synchronized are stored outside the production web package in `content/ktx2-native/{biomes,glb}`; `content/ktx2-native/conversion-progress.json` records source hashes, dimensions, role, uses and output hashes. Results remain authoring sidecars until the renderer can select the appropriate native variant, preserve GLB geometry, samplers, UVs, alpha, color/data semantics and load fallbacks, and pass representative gameplay tests. The original source and runtime resources are not overwritten. The pilot is available only through the development QA option, not enabled by default.

With Vite on port 5175, the encoder dependencies prepared as in `ktx2-atlas-audit.md`, Playwright available and a BC7-capable Edge device:

```powershell
node tools/experiments/inventory_ktx2_sources.mjs
node tools/experiments/plan_biome_ktx2_batch.mjs
node tools/experiments/plan_glb_ktx2_batch.mjs
$env:QA_NATIVE_GPU='1'
node tools/experiments/batch_biome_bc7.mjs .cache/ktx2-fixture/biome-batch.json all biomes
node tools/experiments/batch_biome_bc7.mjs .cache/ktx2-fixture/glb-batch.json all glb
node tools/experiments/sync_native_bc7_sidecars.mjs
```

Batch output first lands in `.cache/ktx2-native`, with source-hash names, color/normal/data classification and a progress report. `sync_native_bc7_sidecars.mjs` checks the container format, color transfer, dimensions and source-hash filename before copying completed files to the trackable authoring area; it does not declare visual acceptance. Batches are restartable and keep successfully generated files. A development-server reload during encoding can invalidate the transcode page; the runner reconnects and retries. The current WASM encoder cannot process 4K images, so they are not silently resized. Future assets outside these plans, other compression formats and any failed records must be accounted for before calling the migration complete.
# Isolated complete-model pilot

The QA-only hyena variant is generated with `node tools/experiments/build_native_glb_pilot.mjs` after its three conversion records exist. It repacks the embedded image buffer views as raw BC7 KTX2 and uses a private required `WG_native_ktx2` extension, rather than incorrectly advertising raw blocks as `KHR_texture_basisu`. The original GLB remains the fallback. The pilot rejects meshopt buffers, shared image views and ambiguous texture roles; it is not a general glTF converter.

On the GTX 1660, `tools/experiments/audit_native_glb.mjs` loaded and rendered both variants without requesting the Basis transcoder. Both had four skinned meshes and 21 bones; the three mapped material textures were compressed in the native variant. In the 512×512 static render, mean absolute channel difference was 0.044/255 and 45 of 1,048,576 channels differed by more than 10. These figures cover one model under laboratory lighting, not contact, gameplay or a global performance improvement. Original GLB: 706,864 bytes; pilot: 647,420 bytes. Evidence: `ktx2-atlas/hyena-native-glb-isolated.json`.

The same comparison also binds both LODs to the real hyena skeleton with `CharacterLod` and samples walking and running at four phases each. The test asserts that motion is visible; these eight samples have mean absolute error below 0.044/255 over the entire frame. This is an isolated camera and lighting setup, not a validation of all actions or gameplay. The opt-in `qa-ktx2-hyena-lod` route selects the native GLB only when BPTC is supported; otherwise the original is used. The flag is available only in development and does not enable the conversion in production.

A real opt-in Worker raid loaded the native hyena LOD through the game asset manager on a GTX 1660, found two compressed color maps and one compressed normal map, and confirmed two attacks without requesting Basis. Two visible skinned meshes shared the model's texture sources at the inspection point. Evidence: `ktx2-atlas/hyena-native-worker-raid.json`. The audit explicitly requests the asset; the visible mesh count does not validate every animation or camera. Concurrent texture conversion contaminated timings, so the run is not an A/B performance measurement. Further visual and gameplay checks and repeatable comparisons are needed before production use.

An isolated ABBA loading probe (`tools/experiments/audit_native_glb_load.mjs`) compares the complete GLB parse and `initTexture`, with a GPU timer and fence. Three contended trials are recorded as `hyena-native-load-contended-{a,b,c}.json`. Each trial estimates texture storage at 262,224 bytes for BC7 versus 1,048,578 bytes for uncompressed RGBA including mipmaps; these are estimates without driver overhead. GPU upload queries were 0.074–0.088 ms for BC7 and 0.440–4.125 ms for the original in those trials. Model parse was noisy, including 185–188 ms native and 219 ms original outliers while the conversion batch was active. Downloads were measured once, before the ABBA samples; these initial trials did not include first draw, shaders or game frametimes. Do not use them to infer a reproducible overall load or FPS improvement; rerun without concurrent conversion and compare real gameplay before accepting the change.

The probe now also measures the first draw and can reverse sample order with `QA_GLB_ORDER=native`. In two additional contended runs, the first draw submitted in 528 ms when the original went first and 497 ms when BC7 went first; subsequent draws were 40–47 ms. Four Three.js programs were present after each draw and none before it, since sample materials were disposed between draws. The first-draw cost is consistent with initialization or shader work shared by both texture formats, but these measurements do not isolate the cause and do not represent gameplay frame pacing. Captures are `hyena-native-first-draw-{original,native}-first-contended.json`.
