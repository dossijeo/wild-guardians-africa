# Visual publication backpressure

The simulation host retains ordered visual publications and pauses dispatch of additional simulation work when the presentation queue reaches 128 pending messages, below its existing 256-message failure limit. Acknowledgements resume dispatch. If the visual channel fails, dispatch resumes without it; the failed graphical presentation is not recreated automatically. Rendering never waits synchronously, but sustained presentation saturation can increase simulation and input latency. This is an overload safeguard, not full temporal independence and not an FPS budget.

Unchanged visual receipts may be folded; eventful publications, pose ownership transitions and incompatible motion traces are not arbitrarily merged. The existing compact pending-step representation remains in use. `node --test tests/visual-publication-stream.test.js tests/worker-game-runtime.test.js tests/host-publication-queue.test.js tests/worker-hosted-runtime.test.js` passes 34 tests, including ordered saturation, resumption, channel failure and event/pose preservation. A real WebGPU raid with Shield also passed as a smoke test. The watermark is not tuned, and real saturation latency, memory consumption, and a bounded recovery strategy remain unmeasured. The long-term requirement to consolidate more eventful states and avoid simulation depending on presentation throughput remains open.
